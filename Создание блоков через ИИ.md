# Создание блоков через ИИ

Новый блок можно описать словами: ИИ сам напишет `block.toml`, шаблон кода и `docs.md`,
проверит их и положит в `user_library/`. Встроенные блоки (`library/`) ИИ менять не может.

## Где это делается

- **Чат в редакторе** — вкладка ИИ справа. Нужен настроенный провайдер ИИ (по умолчанию Claude).
- **MCP-сервер `flp`** — из Claude Code, Claude Desktop или другого MCP-клиента. Проект открывается
  командой `open_project`, дальше ИИ работает теми же инструментами, что и чат.

Инструменты для блоков:

| Инструмент | Зачем |
| --- | --- |
| `list_block_types` | найти похожие блоки (можно фильтровать словами) |
| `get_block_type` | полное описание блока: `block.toml`, шаблон, `docs.md` — образец формата |
| `create_block_type` | создать пользовательский блок: `type`, `block_toml`, `template`, `docs` |

Если блок с таким типом уже есть (встроенный или свой), создание отклоняется — выберите другое имя.
Перед записью `block.toml` проверяется в памяти, поэтому сломанный блок в библиотеку не попадает.

## Как просить

Хороший запрос отвечает на пять вопросов:

1. **Что делает блок** одной фразой.
2. **Входы и выходы**: имя, тип (`bool`, `int`, `float`, `string`), что значат.
3. **Параметры**: что настраивается в свойствах (вывод, время, порог), значения по умолчанию.
4. **Нужна ли память** между циклами (триггеры, счётчики, таймеры, фильтры) — тогда `memory = true`.
5. **Железо и библиотеки**: к какому датчику или шине обращается блок, какую библиотеку Arduino использовать.

Пример запроса:

> Создай блок «Скользящее среднее»: вход `value` (float), выход `avg` (float), параметр `window`
> (int, 2–50, по умолчанию 10) — число последних значений. Блок хранит состояние между циклами.
> Группа «Математика». Сначала посмотри `get_block_type` у похожих блоков.

Подсказки, которые экономят итерации:

- Попросите **сначала посмотреть похожий блок** через `get_block_type`: так ИИ повторит формат и стиль.
- Названия портов и параметров можно по-русски, но проще писать латиницей и добавлять `label`
  по-русски — тогда на схеме красивая подпись.
- Блок с датчиком или шиной: укажите библиотеку (`libraries = [...]`) и заголовок (`includes = [...]`).
- Группа с `/` создаёт вложенные папки: «Насосы/Управление».

## Что должно получиться

Блок — папка `user_library/<группа>/<тип>/`:

```
block.toml        название, группа, входы, выходы, параметры
esp32.cpp.tmpl    шаблон кода (разделы @global, @setup, @loop, @functions)
docs.md           пояснение и пример (по нему ИИ потом подбирает блоки)
```

Полный справочник формата — `library/README.md`. Коротко, что должен соблюсти ИИ:

- в шаблоне все переменные блока начинаются с `{{ id }}` (блоков с одним типом в схеме может быть много);
- входы — `{{ input.имя }}`, выходы — `{{ output.имя }}`, параметры — `{{ param.имя }}`;
- общий код для всех экземпляров — в разделах `once`;
- комментарий с id блока над фрагментом кода, чтобы скетч читался;
- вход без `default` обязателен к подключению;
- выход можно читать в своём же шаблоне — это значение с прошлого цикла.

Мини-пример (`user_library/Математика/scale_clamp/`):

```toml
[block]
type = "scale_clamp"
name = "Масштаб с ограничением"
group = "Математика"
description = "Переводит значение из диапазона входа в диапазон выхода и обрезает по границам."

[[input]]
name = "value"
type = "float"

[[output]]
name = "out"
type = "float"

[[param]]
name = "in_min"
type = "float"
default = 0.0

[[param]]
name = "in_max"
type = "float"
default = 100.0

[[param]]
name = "out_min"
type = "float"
default = 0.0

[[param]]
name = "out_max"
type = "float"
default = 255.0
```

```cpp
// @loop
{
  float t = ({{ input.value }} - {{ param.in_min }}) / ({{ param.in_max }} - {{ param.in_min }});
  t = constrain(t, 0.0f, 1.0f);
  {{ output.out }} = {{ param.out_min }} + t * ({{ param.out_max }} - {{ param.out_min }});
}
```

## Проверка результата

1. Блок появляется во вкладке **«Пользовательские»** библиотеки (редактор перечитывает папку сам).
2. Откройте блок: **правая кнопка → Посмотреть / Изменить блок…** — там видно, как он выглядит на
   плате, и есть вкладка **«Пробная генерация»** со сгенерированным кодом.
3. Поставьте блок на схему, подключите входы и выполните **Проект → Проверить** (F7).
4. **Проект → Код C++** — убедитесь, что код читается и id блока стоит в комментарии.
5. **Собрать** (F5) — компилятор найдёт ошибки в шаблоне. Если ошибка в коде блока, скопируйте
   лог из окна журнала в чат: ИИ поправит шаблон.
6. Для проверки на живой плате — залить и смотреть значения во вкладке отладки.

Править готовый блок можно вручную (редактор блоков) или попросить ИИ. Уже созданный тип
`create_block_type` перезаписать не умеет: для переделки удалите блок
(«Удалить блок…» в контекстном меню) и создайте заново, либо правьте файлы в `user_library/`
— библиотека перечитывается при изменении файлов.

## Типичные ошибки

| Симптом | Причина | Что сказать ИИ |
| --- | --- | --- |
| «тип занят встроенным блоком» | имя совпало с `library/` | «выбери другое имя типа» |
| `block.toml: …` при создании | ошибка формата (тип порта, `default`, `when`) | «исправь block.toml по сообщению» |
| `redefinition of …` при сборке | переменные в шаблоне без `{{ id }}` | «добавь префикс `{{ id }}` ко всем глобальным именам» |
| цикл без блока с памятью | блок участвует в обратной связи | «поставь `memory = true`» (если блок правда хранит состояние) |
| не хватает библиотеки | нет `libraries`/`includes` | «добавь libraries и includes для …» |
| блок не виден в библиотеке | неверная папка/группа или ошибка загрузки | смотрите журнал редактора: предупреждения о пропущенных блоках |

## Безопасность

- ИИ видит и меняет только `user_library/` и текущий проект; встроенные блоки не трогает.
- Шаблон — это код, который попадёт в вашу прошивку. Просмотрите «Пробную генерацию» до заливки,
  особенно для блоков с записью во флеш, сетью или управлением силовыми выходами.
- Пароли и ключи в блоки не вписывайте: для них есть параметры с `local` (хранятся вне файла проекта).
