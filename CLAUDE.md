# FLP_next — аналог FLProg на Rust

Своя программа визуального программирования микроконтроллеров (FBD) в духе FLProg,
написанная с нуля на Rust, со встроенным ИИ-помощником и MCP-сервером.

Полная архитектура и решения: `Аналог FLProg на Rust — архитектура и план.md` в корне.
Перед крупными изменениями сверяйся с ним; если решение меняется — обнови и его.

## Общение и стиль

- Общаемся на русском. Интерфейс программы, сообщения об ошибках и описания блоков — на русском.
- Идентификаторы в коде, имена крейтов и комментарии к коду — на английском.
- Программа пока для одного пользователя: без установщиков и лишней полировки, но код чистый.
- FLProg повторяем по функциональности и раскладке, но не копируем его код, иконки и графику.

## Окружение

- Windows 10/11 x64, 16 ГБ ОЗУ, SSD. Rust — toolchain MSVC (stable).
- Сборка прошивок: `arduino-cli` с ядром `esp32:esp32`. Если чего-то нет — подскажи, как установить, и не ломай сборку остального.
- Целевая плата первой версии: ESP32 (DevKit), заливка и отладка по USB.

## Ключевые решения (кратко)

- GUI: egui (eframe). Генерация прошивки: Arduino C++ через arduino-cli; позже Rust (esp-hal/embassy) — генератор сразу делать с отдельным «выводом» под язык.
- Проект = папка: `project.toml` (плата, настройки), `logic.toml` (блоки и связи), `layout.toml` (координаты, только для редактора). Логика отдельно от координат.
- Блоки с понятными id (`pressure`, `pump`); связи `from = "блок.порт"`, `to = "блок.порт"`. TOML на диске, JSON для ИИ — одни serde-структуры.
- Блоки расширяются файлами без перекомпиляции: `library/<block>/block.toml` + `esp32.cpp.tmpl` (+ `docs.md`); горячая подгрузка. Составные блоки — позже; скриптовые плагины (Rhai/Lua/WASM) — вторая очередь, но точки расширения закладываем.
- Фоновая прекомпиляция с низким приоритетом и постоянной папкой сборки на проект.
- Онлайн-отладка по USB: модуль в прошивке, двоичные кадры с CRC, отпечаток схемы, уставки на лету, форсировка. Транспорт — отдельный слой (Wi-Fi позже).
- ИИ: один общий набор команд (прочитать схему, добавить блок, соединить, проверить, собрать/прошить, читать живые значения, создать блок). Его вызывают и чат в редакторе, и MCP-сервер. Провайдеры через общий трейт, Claude по умолчанию.

## Предлагаемая структура (cargo workspace)

```
crates/
  flp-core/     модель проекта, загрузка/сохранение TOML, библиотека блоков, проверка схемы, порядок выполнения
  flp-codegen/  генерация Arduino C++ из схемы (шаблоны блоков), позже Rust
  flp-build/    вызов arduino-cli: сборка, заливка, кэш, фоновая сборка
  flp-cli/      командная строка: check / gen / build / upload
  (позже) flp-debug, flp-ai, flp-mcp, flp-editor
library/        блоки-файлы
examples/       примеры проектов (начать с насоса из плана)
```

Структуру можно уточнять, но держи границы: ядро не знает про GUI, ИИ и arduino-cli.

## План работ

1. **Ядро** ← начинаем здесь. Готово, когда `flp check examples/pump` находит ошибки схемы
   (несуществующий блок/порт, несовместимые типы, вход без источника, циклы без памяти),
   `flp gen` выдаёт компилируемый скетч, `flp build`/`flp upload` собирают и заливают через arduino-cli.
2. **Базовые блоки**: входы/выходы (цифр., АЦП, ШИМ), DS18B20, DHT22, И/ИЛИ/НЕ/XOR, RS-триггер, фронты,
   TON/TOF, импульс, генератор, сравнение, арифметика, масштабирование, гистерезис, счётчик, сохранение во флеш.
3. **Редактор** на egui: раскладка как в FLProg (сверху меню и инструменты, слева дерево и теги,
   справа библиотека и вкладка ИИ, в центре платы-листы).
4. **Онлайн-отладка** по USB.
5. **ИИ-чат и MCP-сервер**.

## Правила работы

- Перед завершением шага: `cargo fmt`, `cargo clippy --all-targets`, `cargo test`.
- На каждый блок — тест генерации (снимок сгенерированного кода) и пример в `examples/`.
- Сгенерированный скетч должен быть читаемым: комментарий с id блока над каждым фрагментом.
- Не удаляй файлы проекта без явной просьбы.

## Экономия контекста

- Во время работы проверяй только затронутый крейт: `cargo test -p <crate> -q`,
  `cargo clippy -p <crate> --all-targets`. Полный прогон по workspace — только в конце шага.
- `arduino-cli` запускай без `-v`; из длинного вывода показывай только ошибки и предупреждения
  (например, через `| tail` или `grep -E "error|warning"`).
- Не читай `target/`, `.flp/` и `Cargo.lock`; снимки сгенерированного кода читай точечно, не целиком.
- Файл архитектуры читай по нужному разделу (сначала `grep` заголовков), а не целиком.
- Ищи код через `grep`/`Glob` по имени, а не чтением файлов подряд; большие файлы читай диапазонами строк.
- Не запускай субагентов без явной просьбы.
