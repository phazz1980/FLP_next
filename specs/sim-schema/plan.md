# Симуляция всей схемы — план

## Затронутые места
- `crab-core`: ничего нового, берём `check::Report.order` (порядок выполнения), `Logic`, `Library`.
- `crab-sim` (новый модуль `schema`): `Simulation::new(&Project, &Library) -> Result`, `step(dt_ms)`, `set_input(port, value)`,
  `set_manual(port, value)` (для блоков без реализации), `value(port)`, `state(block)`. Один проход = блоки по `order`,
  входы берутся из выходов источников по связям.
- `crab-sim::builtin`: таблица `тип блока -> реализация` (И/ИЛИ/НЕ/XOR, сравнение, арифметика, RS, фронты, TON/TOF, импульс,
  генератор, счётчик, гистерезис, масштабирование…). Реализация — структура с состоянием и методом `step(inputs, params, dt)`;
  значения — `crab_debug::Value`, чтобы редактор показывал их виджетами отладки.
- Пользовательский блок с `block.wasm` — `SimModule` из задачи WASM; блок без реализации — «не симулируется», выходы ручные.
- `crab-editor`: режим «Симуляция» рядом с онлайн-отладкой; `Live`-подобный источник значений подставляется в те же
  виджеты (`debugview::value_label`); кнопки пуск/пауза/шаг/скорость, щелчок по входу меняет значение.

## Формат данных
Не меняется: проект и блоки читаются как есть. Без новых файлов.

## Риски
- Расхождение встроенной Rust-реализации с шаблоном C++ → для каждого блока тест «сценарий входов → ожидаемые выходы»,
  значения сверяются с поведением шаблона вручную при написании.
- Объём: ~116 блоков, часть с железом. Делаем в порядке пользы, остальным — «не симулируется».
- Циклы с памятью и порядок записи переменных: брать тот же порядок, что у генератора.
