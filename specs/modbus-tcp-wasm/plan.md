# План: Modbus TCP в модулях

- `flp-blocks`: новый блок `modbus_tcp_master` (`library/modbus_tcp_master/`, `docs.md`), эмиттер C++ в `uart.rs`
  рядом с `modbus_tcp_slave`; параметры `net`, `host`, `port`, `unit`, период опроса.
- `flp-build/master.rs`: признак `modbus` включается и для TCP-блоков (+ `net`); мастер использует
  общий сетевой интерфейс; проверить размер.
- Мастер прошивки (`master.ino`, секция `modbus`): режимы TCP master/slave на `FLProgModbusTCP` поверх
  `FLP_NET`; коды `modbus(op, …)` те же, добавляются настройки хоста/порта.
- `flp-codegen/wasm.rs` (`modbus_block`): ветка TCP вместо ошибки, настройки через `modbus_cfg`.
- Теги: модель в `flp-core` — признак «публикуется по Modbus» у тега и таблица адресов;
  в проекте-мастере — «внешние теги» (проект-источник, имя, таблица, адрес, тип); редактор:
  команда «Теги → Перенести из проекта…» (выбор проекта, список публикуемых тегов, галочки),
  загрузка источника только на чтение; проверка схемы сверяет тип и наличие. Формат проекта меняется (поле в `logic.toml`) —
  старые проекты читаются без него.
- `flp-sim`: заглушки хоста для TCP, тест сверки со встроенной симуляцией.
- Риски: размер мастера на C3 (сейчас 65% с веб); конфликт порта 502 с веб-сервером; формат файла тегов.
