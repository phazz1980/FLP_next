# Блок на Rust/WASM в прошивке

## Цель
Блок с логикой пишется один раз на любом языке с выходом в WASM (в первую очередь Rust, `no_std`).
Из одного исходника получаются и модуль симуляции (`block.wasm`, как сейчас), и код для прошивки —
без второго описания блока в `esp32.cpp.tmpl`. Расхождение симуляции и платы исключено по построению.
Попутно это первый шаг к блокам на Rust, не меняя остальной конвейер (`arduino-cli`, отладка, заливка).

Направление обратное `specs/template-sim`: там C++-шаблон → WASM для симуляции, здесь WASM → C для прошивки.

## Сценарии
1. В папке блока лежат `block.toml` и `block.wasm` (собранный из Rust), шаблона `esp32.cpp.tmpl` нет.
   Блок можно поставить в схему, `crablogic gen` выдаёт скетч, `crablogic build` собирает его, плата работает как симуляция.
2. У блока есть и `esp32.cpp.tmpl`, и `block.wasm` — для прошивки берётся шаблон (он главнее), модуль идёт в симуляцию.
3. Модуль обращается к чему-то, чего нет в интерфейсе (`crab.input/param/output/log`, `step`, `init`) —
   сборка прошивки отклоняется с понятным сообщением: какой импорт и какого блока.
4. Блок использован в схеме несколько раз — у каждого экземпляра своё состояние.
5. Правлю исходник, пересобираю `block.wasm` — следующая сборка прошивки подхватывает изменение
   (быстрый путь `Direct` продолжает работать, если изменилось только тело скетча).

## Критерии готовности
- Блок-образец (TON или `pulse`) на Rust: `block.wasm` + `block.toml` без шаблона; сгенерированный скетч компилируется
  под ESP32 DevKit; на одном и том же сценарии входов выходы в `crab-sim` и в прошивке совпадают
  (тест-сравнение; запуск на плате — вручную, отмечается отдельно).
- Скетч читаем: код модуля вынесен в отдельный файл скетча, над вызовом в `loop` комментарий с id блока.
- Размер прошивки и время скана блока замерены и записаны в `plan.md` (сравнение с шаблоном C++).
- Снимок генерации для WASM-блока и пример в `examples/`.
- Справка (`help/10-block-editor.md`, `help/05-build.md`), `library/README.md`, новости и файл архитектуры обновлены.

## Вне задачи
Интерпретатор WASM на плате; загрузка блоков без перепрошивки; WASI; полный Rust-вывод генератора (esp-hal/embassy);
модули с динамической памятью и строками; сборка Rust-исходника из редактора (пока `block.wasm` готовят снаружи).

## Решено (приняты предложенные варианты)
1. Интерфейс остаётся на `f64` (как у `crab-sim`). Замер времени скана и размера покажет, нужен ли режим `f32`;
   если нужен — отдельной спекой, не ломая существующие модули.
2. WASM → C переводит `w2c2` (маленький, на выходе обычный C без отдельной среды выполнения).
   Путь к нему — в настройках рядом с `zig_path`. Если на практике не подойдёт (Xtensa, размер) — пробуем `wasm2c`; решение записать в `plan.md`.
3. Шаблон `esp32.cpp.tmpl` главнее модуля; модуль в этом случае идёт только в симуляцию.
4. Первый образец — TON (таймер: есть состояние и время шага).
