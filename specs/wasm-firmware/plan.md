# План: блок на WASM в прошивке

## Идея
Блок с `block.wasm` без шаблона получает **синтетический шаблон**: генератор сам собирает его текст
(как уже умеют `Library::inline_templates`) и пропускает через обычный путь `split_sections`.
Так скетч, порядок выполнения, отладка и быстрая пересборка (`Direct`) работают без изменений.

## Как устроен код блока в скетче
Всё в одном `sketch.ino` (отдельные файлы в папке скетча ломают быстрый путь — `CliReason::SketchFiles`):
- `// @functions once` — C-код модуля, переведённый w2c2, один раз на тип блока; имена с префиксом типа (`crab_<type>_…`).
- `// @global` — состояние экземпляра (память модуля и его глобалы) под именем `<id>_state`.
- `// @setup` — вызов `init`.
- `// @loop` — запись входов и параметров в массивы, вызов `step(dt_ms)`, чтение выходов в переменные порта.
- Хост-функции `crab.input/param/output/log` — статические заглушки над массивами экземпляра (`log` → пусто или `Serial` в отладочной прошивке).
- Над каждым фрагментом комментарий с id блока.

## Где что делается
- `crab-build::wasm` — новая функция перевода: `block.wasm` → `block.wasm.c` рядом, с меткой `block.wasm.c.generated`
  (как у сборки модуля из C++). Запускает `w2c2`; путь — настройка `w2c2_path`.
  Генератор сам внешних программ не запускает: он читает готовый `block.wasm.c`, нет файла — ошибка
  «выполните перевод блока» с указанием блока. `crablogic build`/`crablogic gen` в CLI вызывают перевод заранее, если файл устарел.
- `crab-core::library` — признак «у блока есть модуль»; приоритет: шаблон > модуль (сценарий 2).
- `crab-codegen::arduino` — в `render_block` ветка: нет шаблона, есть `block.wasm.c` → синтетический шаблон.
  Проверка импортов модуля (только `crab.*`) — при переводе, чтобы ошибка была до генерации.
- `crab-sim` — без изменений; тест сравнения симуляции и скомпилированного кода блока.
- Редактор: кнопка/автоперевод при сохранении блока (как сборка модуля), поле `w2c2_path` в настройках.

## Формат данных
Новых полей в `block.toml` нет. Новые файлы в папке блока: `block.wasm.c`, `block.wasm.c.generated`.

## Риски
- w2c2 на Xtensa/Arduino-ядре (компилятор, `-Werror`, отсутствие `<math.h>`-функций): проверить в первой задаче.
- `f64` на ESP32 — программный double: измерить.
- Размер: память модуля в RAM, раздувание кода; задать лимит памяти модуля для прошивки (малый, например 64 КиБ).
- Модули со своей памятью > лимита или с импортами сверх `crab.*` отклоняются.
- Имена: коллизии символов между экземплярами/типами — префиксы.
- Отладочный модуль и отпечаток схемы: блок должен вести себя как обычный (значения портов — обычные переменные).

## Результаты прототипа (задача 1, 1 ноября 2026)
Стенд: `proto/ton_rs/ton.rs` → `block.wasm` (600 байт) → `w2c2` (собран `zig cc`, `tools/w2c2-src/bin/w2c2.exe`) → `ton.c`;
скетч `proto/sketch`, базовый вариант на чистом C++ — `proto/base`. Плата ESP32 DevKit, ядро esp32 2.0.17, только компиляция.
- **Компилируется** `arduino-cli` под ESP32 без правок `w2c2_base.h` (Xtensa, `<math.h>` есть). Хост-функции — обычные C-функции `i4_crab5_input` и т. п., без таблицы импортов.
- **Flash:** 262 789 против 262 289 байт у C++ — **+500 байт**. **Статическая RAM:** +56 байт.
- **Память модуля:** `wasmMemoryAllocate` берёт `calloc` целыми страницами по 64 КиБ — **64 КиБ кучи на экземпляр блока**. Для схемы из десятков блоков недопустимо.
  Нужен свой аллокатор: статический буфер размером с реальные данные модуля (у TON хватило бы 1 КиБ — стек `-zstack-size=1024`).
  Без этого стек Rust по умолчанию тянет 1 МиБ (17 страниц), поэтому модуль надо собирать с малым стеком и проверять `initial-memory` при переводе.
- **`w2c2_base.h`** — 2307 строк, подтягивает `pthread`/`windows.h` по условиям; для скетча нужно сократить до нужного подмножества и вставить в `// @functions once`.
- **Не измерено:** время скана на плате (порты COM3/COM4/COM12 найдены, какая из них ESP32 — неизвестно, заливку без вашего слова не делал).
- **Не решено:** `f64` оставили как есть; замер времени на плате покажет, нужен ли `f32`.
- Вывод: путь A жизнеспособен; главная доработка — память (задача 3/5), а не размер кода.

### Замер на плате (1 ноября 2026)
Плата на COM5 оказалась **ESP32-C3** (RISC-V, 160 МГц, без FPU; `esp32:esp32:esp32c3:CDCOnBoot=cdc`), не классический ESP32. Прошивки залиты, вывод прочитан.
- Flash на C3: 241 860 (WASM → C) против 241 312 (C++) — +548 байт.
- Время одного шага TON: **2,76 мкс** (WASM → C) против **1,45 мкс** (C++); ×1,9. Выход `out=1` после 1000 мс при уставке 1000 — логика верна.
- На 1000 таких блоков скан занял бы ~2,8 мс; для логики схем накладные расходы приемлемы. `f64` на C3 программный, режим `f32` — отдельным шагом, если понадобится.
- Побочный вывод: на RISC-V плате (C3/C6) Rust работает без форк-тулчейна `espup`, путь B (полный Rust-вывод) там проще.
- Классический ESP32 (Xtensa) этим замером не проверен — только компиляция.
