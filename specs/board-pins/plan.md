# План: выводы платы с функциями

Две очереди: сначала GPIO и функции (всё решено), потом выводы расширителей платы.

## Очередь 1. GPIO и функции

**Формат `board.toml`.** В `[[pin]]` необязательный `functions = ["din", "dout", "pwm", "adc", "dac"]`.
Нет списка — функции берутся из таблицы чипа (как сейчас). Список есть — только он, но не шире чипа
(`validate` ругается по-русски: «у GPIO34 нет функции pwm у ESP32»).

**flp-core.**
- `pins.rs`: `PinFunction {Din, Dout, Pwm, Adc, Dac}` (serde — `din`…`dac`, `label()` по-русски);
  у `PinInfo` поле `functions` — набор, считается по чипу (`din` везде, кроме флеш-пинов; `dout`/`pwm`
  — не на `input_only`; `adc` — если есть АЦП; `dac` — GPIO25/26 у ESP32); `fits(mode)` смотрит в набор.
  `on_board(label, busy, functions)` сужает набор.
- `library.rs`: `PinMode` получает `Pwm` и `Dac`; `library/pwm_out/block.toml` — `mode = "pwm"`.
- `boards.rs`: `BoardPin.functions: Option<Vec<PinFunction>>`; проверка; `layout()` передаёт функции.
- `check.rs`: сообщение «вывод GPIOn не умеет …» по режиму (АЦП / ШИМ / выход / вход).

**flp-editor.**
- `blockedit.rs`: режимы в списках — «ШИМ», «ЦАП».
- `boardedit.rs`: таблица стартует пустой (`Form::new_board` без строк); `PinRow` = GPIO + название +
  заметка + «занят» + набор функций; кнопка «+ Вывод» (выпадающий список ещё не добавленных GPIO),
  кнопка удаления строки, чекбоксы функций (недоступные чипу — серые); `to_def` всегда пишет `[[pin]]`
  с `functions`; пустая таблица — «добавьте хотя бы один вывод»; смена чипа убирает функции,
  которых у нового чипа нет. Старая плата без `[[pin]]` открывается со всеми выводами чипа.

**Риски.** `plain`-логика «все выводы без описания = нет таблицы» исчезает: старые файлы читаются,
но при сохранении получат явные `[[pin]]`. Снимки примеров не должны меняться (`fits` по умолчанию тот же).

## Очередь 2. Выводы расширителя платы

**Формат.** Отдельная таблица `[[expander_pin]]` (`BoardExpanderPinDef`): `device` (id из `[[device]]`),
`pin`, `name`, `note`, `functions` (только `din`/`dout`). Микросхема, адрес и шина берутся из устройства
(`DeviceDef::expander()` — пока PCF8574 по `kind = pcf8574_out/pcf8574_in`). `BoardDef::validate` проверяет
устройство, номер вывода, функции, повторы.

**flp-core.** `pins.rs`: `BoardExpander {title, expander, pins}`, `BoardExpanderPin`, `fits(pin, mode)`;
`BoardLayout::{expanders, expander_for}`. `check.rs`: `check_board_expanders` — блок на расширителе, совпадающем
с расширителем платы, должен стоять на выведенном выводе с нужной функцией.

**flp-editor.** `dialogs.rs`: у входа и выхода один список выводов (`pin_rows` → `PinRow`/`PinChoice`): GPIO,
выводы расширителей проекта и выводы расширителей платы, которых в проекте ещё нет. Выбор строки задаёт
`PinSource` и вывод; для расширителя платы заводится `d.pending` из шаблона (`board_expander`) под свободным
id, форма «Новый расширитель» для него скрыта. У платы без таблицы выводов остаётся прежняя пара «источник +
вывод». `panels.rs`: «+» входа/выхода кладёт блок без позиции на листе (`add_to_tree`), строки дерева
перетаскиваются (`drag_row`, `DragItem::Topic`); `doc.rs`: `place_unplaced` не ставит такие блоки на лист при
открытии. `boardedit.rs`: таблица «Выводы
расширителей» на вкладке «Выводы» (`ExpanderPinRow`, «+ Вывод расширителя ▾»), удаление или смена id устройства
переносит его выводы.

**Риски.** Расширитель проекта «тот же» только при совпадении чипа, адреса и шины; при изменении адреса в проекте
блок перестаёт совпадать с платой и проверка не ограничивает его выводы (так и задумано).

Файл архитектуры и `library/README.md` обновляются в конце каждой очереди.
