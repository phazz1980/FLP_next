# Копии входов и выходов на плате

## Зачем

Вход или выход (блок с выводом платы, «тег» в дереве слева) нужен в нескольких местах схемы.
Сейчас перетаскивание тега из дерева на плату переносит единственный блок на новое место.
Нужно, как в FLProg: тег ставится на плату сколько угодно раз.

## Сценарии

1. Тега ещё нет на плате — перетаскивание ставит сам тег (как раньше).
2. Тег уже на плате — перетаскивание создаёт **копию** в точке сброса. Копия — ссылка на тег:
   в дереве одна строка, вывод, режим и прочие параметры общие. Двойной щелчок по копии
   открывает свойства тега; изменения действуют на все копии.
3. Копия входа выдаёт то же значение, что тег, в том же цикле (вывод читается один раз).
4. Копия выхода пишет в вывод сама; если подключены несколько копий, побеждает последняя
   по порядку выполнения (как в FLProg).
5. Удаление тега с платы при живых копиях: тег встаёт на место первой копии со всеми её
   связями, а копия исчезает. Удаление копии убирает только её.
6. Переименование тега обновляет ссылки копий.

## Критерии готовности

- Копия не даёт ошибки «вывод занят»; копия с битой ссылкой (нет тега, другой тип,
  ссылка на копию, тип без вывода) — ошибка проверки.
- В скетче копия входа — присваивание после чтения тега; копия выхода — только код цикла
  шаблона (без `setup` и глобальных).
- Снимок генерации и пример `examples/tag_copies`.
- ИИ и MCP видят копии в схеме (`tag`), правки параметров копии уходят в тег.

## Вне задачи

- Копии других блоков (не тегов), копии переменных (у них уже есть блоки чтения/записи).
- Отдельная команда ИИ «создать копию тега» — позже, если понадобится.
