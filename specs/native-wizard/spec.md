# Мастер нативной части блока («Библиотека Arduino»)

## Цель
Пользователь без знания C++ делает блок для датчика на библиотеке Arduino (пример — GyverHX711) за несколько шагов,
не набирая структуру `native.cpp` руками. Мастер собирает файл из полей; места для ошибки — только короткие
выражения вызовов, которые проверяет сборка.

## Сценарии
1. Вкладка «Код C++ для платы» → «Создать по шаблону» → «Библиотека Arduino (мастер)»: шаги 1–5, на шаге 6 виден
   готовый код (только чтение) и кнопка «Собрать мастер для проверки».
2. Кнопка «Править код» переводит блок в обычный режим (текст `native.cpp`); из него в мастер вернуться нельзя.
3. Блок с кодом от мастера при повторном открытии снова открывается в мастере (поля хранятся в самом `native.cpp`
   в служебном комментарии), пока код не правили вручную.

## Шаги
1. **Библиотека:** имя в менеджере Arduino, файл `.h`.
2. **Объект:** класс; аргументы конструктора — каждый «параметр блока» (создаётся тут: имя, тип пин/число) или константа.
3. **Запуск:** необязательные вызовы один раз (`begin()`), выражения.
4. **Выходы:** строки «имя, тип (bool/int/float), выражение, условие обновления (необязательно)».
5. **Действия:** строки «вход (bool, создаётся тут), по фронту, вызов».
6. **Проверка:** код и сборка.

## Критерии готовности
- По шагам для GyverHX711 получается файл, равный по смыслу проверенному вручную (условие `value` берётся от выхода `ready`); он проходит `parse_native` и собирается в мастер.
- Ошибки шагов видны сразу, по-русски: пустое имя, повтор имени, не-латиница, пустое выражение, неизвестный параметр
  в аргументах.
- Параметры, входы и выходы шагов попадают в `block.toml` формы блока без ручного переноса.
- Справка `help/10-block-editor.md` описывает мастер.

## Вне задачи
Чтение методов из заголовка `.h`; заполнение ИИ по ссылке; I²C по регистрам и 1-Wire в мастере (после этого);
строки в нативной части.
