# План: мастер нативной части

- `crab-core::native::wizard` — модель `LibraryWizard { lib, header, class, args, init, outputs, actions }`,
  `validate() -> Vec<текст по-русски>`, `generate(&self) -> String` (чистая функция), разбор обратно из служебного
  комментария `// crab:wizard {json}` в первой строке после `crab:native` (serde_json — уже в зависимостях ядра; иначе TOML).
- `generate`: `State` с указателем на объект и `prev_<вход>` на каждое действие; `CRAB_INIT` — `delete` и `new Класс(арг...)`
  + запуск; `CRAB_STEP` — действия по фронту, выходы (с условием `if (...)`, иначе безусловно).
- `crab-editor::blockedit`: состояние мастера в `Form`, шаги как подвкладки; на каждом шаге добавляет/правит строки
  параметров, входов и выходов формы (общая функция с `apply_template`); шаг 6 — код только для чтения и `NativeBuild`.
- Тесты: снимок кода для HX711 (`crab-core`), валидация, круг «generate → parse wizard → generate», `parse_native`
  на результате; игнорируемый тест сборки в `crab-build` (из `master_with_template_blocks_compiles`).
- Риски: расхождение формы блока и шагов (решаем: шаги владеют своими строками формы, помеченными в форме); ручная
  правка `block.toml` после мастера — комментарий в коде перестаёт совпадать, тогда режим «код».
