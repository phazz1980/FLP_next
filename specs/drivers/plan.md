# Нативная часть блока и скриптовые блоки — план

Спека: `spec.md` (решения от 06.11.2026 записаны в ней). Собираем по слоям; каждый полезен сам.

## Затронутые крейты
- **crab-core** — разбор `native.cpp` (аннотации `// crab:`, `CRAB_INIT`, `CRAB_STEP`), поле блока `native`/`logic` в
  `block.toml`, горячая подгрузка, проверка схемы (нативная часть есть и совпадает с интерфейсом).
- **crab-script** (новый) — лексер, разбор, проверка типов, русские ошибки с номером строки, вывод в WASM (ABI v3,
  32-битные значения, как в `crab-codegen::wasm`).
- **crab-codegen** — скриптовые блоки в выводе «лист → WASM»; блок с нативной частью — вызов `step` экземпляра в цикле мастера.
- **crab-build** — `master.rs`: `MasterFeatures` получает нативные части блоков проекта (в `master_sketch_id`, то есть в
  отпечаток); `native.cpp` копируется в скетч мастера, экземпляр на каждый блок схемы.
- **crab-sim** — скриптовый блок работает в симуляции; нативная часть заменяется заглушкой из `// crab:sim`.
- **crab-editor** — вкладка «Нативная часть» в редакторе блока (вместо отдельного раздела «Конструктор драйвера»); кнопки
  «Создать по шаблону»; «Собрать мастер для проверки».
- **crab-ai / crab-mcp** — после формы: команды `create_block` с нативной частью и логикой в общем наборе.

## Формат
`library/<блок>/native.cpp`:
```cpp
// crab:native libs="Adafruit BMP280" i2c=0x76
// crab:sim temperature=21.5 pressure=101325
#include <Adafruit_BMP280.h>
struct State { Adafruit_BMP280 bmp; };
CRAB_INIT(State& s, Params p)            { s.bmp.begin(p.address); }
CRAB_STEP(State& s, In in, Out& out)     { out.temperature = s.bmp.readTemperature(); out.pressure = s.bmp.readPressure(); }
```
Типы `In`/`Out`/`Params` генерируются из `block.toml` (имена портов и параметров). Допустимы `bool`/`int`/`float`.
В скетч мастера файл копируется как есть, экземпляр блока получает свой `State`. Ошибки разбора — по-русски с номером строки.
Логика: `logic.crs` рядом; блок без обеих частей остаётся блоком-шаблоном (`esp32.cpp.tmpl`).

## Язык логики (подмножество)
`let x: int = 0;`, `if`/`else`, `while`, `fn`, `return`, `bool`/`int`/`float`, арифметика и сравнения как в числовой модели
(`specs/numeric-model`); `state` — переменные между шагами. Нет: строк, массивов, структур, рекурсии (первая версия).

## Риски
- Собственный компилятор — главная работа; ограничиваем язык, снимки и сверка с `crab-sim` на каждый оператор.
- Мастер под проект: несколько вариантов прошивки; кэш сборки по набору нативных частей, как уже по `MasterFeatures`.
- Порядок вызова `step` у блоков в мастере и связь с шагами модулей — как у встроенных блоков в `wasm-on-mcu`.
- Перенос DHT22/DS18B20/Modbus/MQTT — не в этой спеке, один пример (I²C-датчик) для проверки.
- Решение меняет архитектуру: после первых задач дописать раздел в `Архитектура и план.md`.
