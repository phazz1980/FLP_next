# Драйверы и конструктор драйвера — план

Спека: `spec.md` (решения от 06.11.2026 записаны в ней). Как: собираем по слоям снизу вверх, каждый слой полезен сам.

## Затронутые крейты
- **crab-core** — разбор `drivers/<имя>/driver.cpp` (аннотации и `CRAB_EXPORT`), загрузка драйверов (рядом с библиотекой блоков,
  горячая подгрузка), проверка: у блока `uses = [...]` есть драйвер, функции и типы совпадают.
- **crab-script** (новый) — язык скриптовых блоков: лексер, разбор, проверка типов, русские ошибки с номером строки,
  вывод в WASM (ABI v3, 32-битные значения, как в `crab-codegen::wasm`). Вызовы драйверов превращаются в импорты `drv.<имя>.<функция>`.
- **crab-codegen** — скриптовый блок подключается к выводу «лист → WASM»; права `allow` в `module.toml` берутся из `uses`.
- **crab-build** — `master.rs`: мастер собирается из драйверов проекта (`MasterFeatures` получает список драйверов, он входит в
  `master_sketch_id`, то есть в отпечаток); `driver.cpp` подключается в скетч мастера; вызовы импортов — таблица `drv`.
- **crab-sim** — скриптовый блок работает в симуляции; драйвер в симуляции — заглушка с заданными значениями (из `driver.toml`).
- **crab-editor** — раздел «Конструктор драйвера»: шаблон по типу подключения (GPIO/1-Wire, I²C с таблицей регистров, SPI,
  UART/Modbus, библиотека Arduino), форма, предпросмотр `driver.cpp`, кнопка «собрать мастер для проверки».
- **crab-ai / crab-mcp** — позже (после формы): команды `create_driver`, `create_script_block` в общем наборе.

## Формат
Один файл `drivers/<имя>/driver.cpp`:
```cpp
// crab:driver name="bmp280" title="BMP280" libs="Adafruit BMP280" i2c=0x76
// crab:sim read_temp=21.5 read_pressure=101325
#include <Adafruit_BMP280.h>
static Adafruit_BMP280 bmp;
CRAB_INIT()  { bmp.begin(0x76); }
CRAB_EXPORT float read_temp()     { return bmp.readTemperature(); }
CRAB_EXPORT float read_pressure() { return bmp.readPressure(); }
```
Разбор (в `crab-core`) читает строки `// crab:...`, `CRAB_INIT` и объявления `CRAB_EXPORT <тип> <имя>(<аргументы>)`; типы только
`bool`/`int`/`float`, иначе — ошибка по-русски с номером строки. В скетч мастера файл копируется как есть, макросы
регистрируют функции под импортами `drv.<имя>.<функция>`. Конструктор генерирует такой же файл по шаблону; ручные правки не
теряются, потому что он читает сам файл. Скриптовый блок: `block.toml` с `uses = ["драйвер"]` + `logic.crs`.

## Язык (подмножество)
`let x: int = 0;`, `if`/`else`, `while`, `fn`, `return`, `bool`/`int`/`float`, арифметика и сравнения как в числовой модели
(`specs/numeric-model`). Имена входов, выходов, параметров — готовые переменные; `state` — переменные, живущие между шагами.
Нет: строк, массивов, структур, рекурсии (первая версия). Размер модуля и число шагов проверяются заранее.

## Риски
- Собственный компилятор — основная работа; ограничиваем язык и ставим снимки/сверку с `crab-sim` на каждый оператор.
- Мастер «под проект»: несколько вариантов прошивки; кэш сборки по списку драйверов, как уже по `MasterFeatures`.
- Перенос DHT22/DS18B20/Modbus/MQTT — не в этой спеке, только пример одного драйвера (I²C-датчик) для проверки.
- Решение меняет архитектуру: после первых задач дописать раздел в `Архитектура и план.md`.
