# Драйверы и конструктор драйвера — задачи

Порядок важен: каждая задача проверяется до следующей.

- [ ] 1. Формат драйвера: `driver.toml` в `crab-core`, загрузка из `drivers/`, проверка `uses` блока. Проверка: тесты загрузки,
  ошибки по-русски (нет драйвера, нет функции, не тот тип).
- [ ] 2. `crab-script`: лексер и разбор подмножества языка. Проверка: тесты на примерах, ошибки с номером строки.
- [ ] 3. `crab-script`: проверка типов и вывод в WASM (без драйверов). Проверка: сверка с `crab-sim`, как у встроенных блоков.
- [ ] 4. Скриптовый блок в схеме: `logic.crs` в `block.toml`, сборка листа с таким блоком, `uses` -> `allow` в `module.toml`.
  Проверка: пример в `examples/`, снимок модуля.
- [ ] 5. Мастер «под проект»: драйверы в `MasterFeatures`, `driver.cpp` в скетче, отпечаток. Проверка: сборка мастера с двумя
  драйверами и без, разные отпечатки.
- [ ] 6. Вызовы драйверов из скрипта: импорты `drv.*`, заглушки драйвера в симуляции. Проверка: скрипт с драйвером в `crab-sim`.
- [ ] 7. Проверка схемы: нужного драйвера нет в мастере на плате — сообщение по-русски, что нужна сборка мастера; редактор
  показывает, что доступно без перепрошивки.
- [ ] 8. Конструктор драйвера в редакторе: шаблоны GPIO/1-Wire и I²C (таблица регистров), форма, предпросмотр кода,
  сборка мастера для проверки, сохранение ручных правок между маркерами. Проверка: I²C-датчик на заглушке собирается в `arduino-cli`.
- [ ] 9. Шаблоны SPI, UART/Modbus, библиотека Arduino. Проверка: сборка по одному примеру на каждый.
- [ ] 10. Заготовка скриптового блока после создания драйвера. Проверка: пример «драйвер + блок + схема» до заливки модуля.
- [ ] 11. Справка (`help/`), `docs.md`, раздел в `Архитектура и план.md`; перевод справки следом.
- [ ] 12. После формы: ИИ-режим конструктора (`create_driver`, `create_script_block` в общем наборе ИИ).
- [ ] 13. Сверка с критериями спеки; не проверено на железе — записать.
