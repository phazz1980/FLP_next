# Нативная часть блока и скриптовые блоки — задачи

Скриптовый язык (задачи 5–7, 10) отложен: датчики только отдают данные, а логика строится блоками схемы (решение 9 в спеке).

Порядок важен: каждая задача проверяется до следующей.

- [x] 1. Формат нативной части: разбор `native.cpp` (`// crab:native`, `// crab:sim`, `CRAB_INIT`, `CRAB_STEP`) в
  `crab-core::native`, `LibraryBlock::native_part()`, проверка при загрузке блока (битый файл — блок не попадает в библиотеку,
  `Error::InvalidNative`), проверка типов портов и `crab:sim` по интерфейсу. Полей `native`/`logic` в `block.toml` нет: часть есть,
  если лежит файл. Проверено: 8 тестов (разбор, ошибки по-русски с номерами строк, типы, загрузка из папки).
- [x] 2. Мастер из нативных частей: `crab_build::native` (`NativeBlock`, `collect_natives`, `glue`), `MasterFeatures.natives`
  (больше не `Copy`), `#define CRAB_NATIVE`, библиотеки из `crab:native libs`, отпечаток учитывает исходник, число экземпляров и порты.
  В `master.ino`: право и импорт `native(kind, inst, in, out)`, маркер `// @crab-native-glue` после includes; весь код склейки в
  `namespace crab_native` (иначе препроцессор Arduino ставит прототипы раньше типов wasm3). Проверено: 4 теста склейки и отпечатка;
  `cargo test -p crab-build --test build master_with_native -- --ignored` собирает мастер для ESP32 с двумя блоками (один — в 2
  экземплярах); сборка мастера с веб-страницей не сломалась. Не проверено: выполнение на плате (модуль ещё не вызывает `native`,
  это задача 7) и независимость состояний экземпляров в работе (в коде — отдельный `State` на экземпляр).
- [x] 3. Заглушка нативной части в симуляции: значения `// crab:sim` становятся начальными выходами блока (`crab-sim`, узел
  остаётся «ручным», выходы можно менять мышью, `reset` возвращает к значениям `crab:sim`); ошибка в `native.cpp` попадает в
  `Simulation::notes`. Проверено: `crates/crab-sim/tests/native_sim.rs` (2 теста), весь workspace (fmt, clippy, test) зелёный.
- [x] 4. Проверка мастера на плате: мастер сообщает `id=` (отпечаток) и `native=` (тип:экземпляры) в ответе `stats`
  (`master.ino`, `#define CRAB_MASTER_ID`/`CRAB_NATIVE_KINDS` генерируются в скетч); `mcu_module::wait_for_master_info`,
  `crab_build::master_state` (`Current`/`Unknown`/`Differs`/`MissingNative`). Редактор: «Залить модули» останавливается с русским
  сообщением, если в мастере нет нативной части блока (или мало экземпляров); в строке состояния при отладке — «Мастер на плате
  актуален / собран иначе / нет нативной части»; `master_features(project, lib)` теперь кладёт нативные части в мастер. Решение
  отличается от обсуждённого: отдельной команды `id` нет, поля идут в уже существующий ответ `stats` (старый мастер без них — «неизвестен»).
  Проверено: тесты `crab-build` (разбор `stats`, состояния мастера, определения в скетче) и `crab-debug`; fmt, clippy, весь workspace.
  Не проверено: на плате (мастер с `id=` не прошивался), вид строки состояния в окне, переводы новых строк в `i18n/*.json`.
- [ ] 4а. Вывод «лист → WASM»: блок с нативной частью вызывает `crab.native(kind, inst, in, out)` (входы и параметры — слова в памяти
  модуля, выходы — из ответа), право `native` в `module.toml`, номера `kind`/`inst` из `native_kind` и порядка блоков. Проверка: модуль
  листа с нативным блоком проходит `wasm-validate`, снимок; на плате датчик отдаёт значение в схему (нужна плата). Без этой задачи
  нативная часть собирается в мастер, но схема её не вызывает.
- [ ] **Отложено** 5. `crab-script`: лексер и разбор подмножества. Проверка: тесты на примерах, ошибки с номером строки.
- [ ] **Отложено** 6. `crab-script`: проверка типов и вывод в WASM. Проверка: сверка с `crab-sim`, как у встроенных блоков.
- [ ] **Отложено** 7. Блок с `logic.crs` в схеме: сборка листа, права `allow`. Проверка: пример в `examples/`, снимок модуля.
- [ ] 8. Редактор блока: вкладка «Нативная часть» (C++-редактор, заголовки, пробная генерация), «Собрать мастер для проверки».
  Проверка: I²C-датчик на заглушке собирается в `arduino-cli`.
- [ ] 9. Шаблоны «Создать по шаблону»: GPIO/1-Wire, I²C с таблицей регистров, SPI, UART/Modbus, библиотека Arduino. Проверка:
  сборка по одному примеру на каждый.
- [ ] **Отложено** 10. Вызовы нативных функций из скрипта (`CRAB_EXPORT`, `uses`) — второй шаг; заглушки в симуляции.
