# Встроенные блоки на Rust: шаг 3 (железо)

## Цель
Довести перенос до конца: у встроенных блоков с железом тоже нет `esp32.cpp.tmpl`, а C++ выдаёт Rust-тип из `crab-blocks`.
Тогда остаётся один путь выдачи кода (Rust-блок > `block.wasm`), а шаблоны — только у пользовательских блоков.

## Что осталось (по группам, строк шаблона)
1. Входы и выходы: `digital_in` (расширитель, подтяжка, инверсия), `digital_out`, `analog_in`, `pwm_out` — 2–7 строк.
2. Датчики и прочее: `dht22`, `ds18b20`, `flash_store`, `dms`, `cycle_report`, `decoder`, `encoder` — 0–20 строк, нужны библиотеки Arduino.
3. Расширители: `pcf8574_in`, `pcf8574_out` — около 30 строк, общая шина I2C.
4. UART и Modbus: `uart_*`, `modbus_*` — до 77 строк, контекст `{{ uart.* }}`.
5. Сеть: `wifi`, `ethernet`, `mqtt*`, `ntp` — 30–330 строк.
6. Веб-интерфейс: `web_*` (17 блоков, `web_ui` — 437 строк, `web_net` — 121).

Вне задачи: Rust-вывод (`esp-hal`), формат `block.toml` и проекта, симуляция блоков с железом.

## Критерии готовности
- У блоков выбранных групп нет `esp32.cpp.tmpl`; снимки и скетчи `examples/` не изменились побайтно.
- Побайтное сравнение со старым выводом на проекте из всех перенесённых блоков с вариантами параметров.
- Ветка «шаблон в папке главнее Rust-блока» остаётся только для пользовательских блоков.
- Справка, `library/README.md`, новости, архитектура обновлены.

## Ответы
1. Берём группы 1–3 (простое железо) сейчас; UART/Modbus, сеть и веб — отдельными шагами.
2. Сначала только перенос кода; затем по просьбе добавлена симуляция чистой логики (`dms`, `decoder`, `encoder`, `flash_store`, `cycle_report`). У блоков с пинами и датчиками `behavior()` — `None`: им нужен виртуальный стенд.
3. `CppCtx` расширен контекстом расширителя пинов (`expander`); контекст UART — в шаге с UART.
