# Параметры сетевых блоков как входы на самом блоке

## Цель
У блоков Wi-Fi, Ethernet и клиента MQTT (и, по желанию, публикации/подписки) любой параметр можно
сделать входом прямо на блоке, стоящем на листе, — без промежуточной переменной. Сейчас такие
параметры «вытаскиваются» на плату только через переменную (`[block.bind]`), а галочка «Вход»
(`param_in`, спека `param-inputs`) есть только у числовых параметров и не показывается у скрытых
сетевых блоков.

## Сценарии
1. Перетаскиваю Wi-Fi на лист целиком (значок ▢). В левой панели у каждого параметра (SSID, пароль,
   IP, шлюз, брокер, порт…) есть галочка «Вход».
2. Ставлю её у `ssid` — у блока на листе появляется вход `ssid` (строка); подаю на него выход
   другого блока.
3. Не подключён — действует значение параметра из панели.
4. Снимаю галочку — вход исчезает, связь на него удаляется.

## Критерии готовности
- Галочка есть у всех параметров этих блоков, кроме списков выбора (`net`, `wifi_mode`, у которого
  уже есть вход `mode`) и флагов `use_*`/`out_*`.
- Типы входов: int/float/bool/время — как в `param-inputs`; text → строка.
- Изменение значения на лету перенастраивает сеть (переподключение при смене SSID/пароля/брокера).
- Сохранение: `param_in = [...]` в блоке; проверка схемы, симуляция и снимки кода — как у `param-inputs`.
- Справка и `Архитектура и план.md` обновлены.

## Вне задачи
Параметры со списками выбора; пароль Wi-Fi, хранящийся программой (`local`), остаётся вне файла
проекта, даже если приходит со входа.

## Вопросы
1. Строковый вход SSID/пароля/брокера — **ответ: обновлять на лету** (Wi-Fi готово, переподключение по хешу настроек; Ethernet и MQTT-клиент — не сделано).
2. Нужен ли вход и на публикации/подписке MQTT (`topic`, `retain`), или только на трёх блоках?
3. Старый способ «через переменную» оставить рядом?
