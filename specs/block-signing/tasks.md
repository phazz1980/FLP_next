# Подпись наборов блоков — задачи

Предусловие: закончена `specs/block-packs/`; хеш `sha2` общий с `specs/block-registry/`.

- [ ] 1. `sign.rs`: ключи, `key_id`, `sign_pack`, `verify_pack` для подписи. Проверка: roundtrip-тест.
- [ ] 2. Подмена файла и подмена `pack.toml` ломают проверку. Проверка: два теста.
- [ ] 3. `author` в `pack.toml` и в подписи должны совпасть. Проверка: тест `AuthorMismatch`.
- [ ] 4. `TrustStore`: загрузка авторов, локальные доверенные, отзыв. Проверка: тесты (известный, неизвестный, отозванный).
- [ ] 5. Состояния `Trust` в `IncomingPack`, проверка до записи файлов. Проверка: тест на каждое состояние, при `Invalid` библиотека не меняется.
- [ ] 6. Обновление набора от другого автора даёт вопрос. Проверка: тест.
- [ ] 7. Редактор: создание ключа, DPAPI-хранилище. Проверка: вручную, файл ключа из другого профиля не открывается.
- [ ] 8. Экспорт подписывает; без ключа предложение создать. Проверка: вручную.
- [ ] 9. Окно импорта: состояния, «Доверять», «Всё равно установить», запреты. Проверка: вручную на каждом состоянии.
- [ ] 10. Значки в дереве блоков (без подписи, отозванный ключ). Проверка: вручную.
- [ ] 11. Загрузка `authors/*.toml` вместе с индексом каталога, локальная копия. Проверка: вручную, без сети используется копия.
- [ ] 12. Раздел про подписи в файле архитектуры.
- [ ] 13. Сверка с критериями спеки; не проверенное (реальная сеть, DPAPI на другом профиле) записать сюда.
