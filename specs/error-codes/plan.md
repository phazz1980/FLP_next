# Коды ошибок — план

- `flp-core/check.rs`: `enum DiagKind` (по виду на каждое сообщение), поле `kind: DiagKind` в `Diagnostic`, метод `DiagKind::id() -> &'static str` (стабильный идентификатор вроде `duplicate_id`). Мест создания `Diagnostic` три (конструкторы в `check.rs`), остальные сообщения идут через них.
- `flp-core`: `DiagKind::ALL` для перебора в тесте.
- `flp-editor/help.rs`: таблица «вид → страница и якорь», строки таблицы в `help/08-errors.md` получают заголовки или идентификаторы, по которым тест их находит.
- `flp-editor/app.rs`: ссылка «Что это?» в панели сообщений; `flp-ai`/`flp-mcp`: поле `kind` в ответе `check`.
- Риск: изменение структуры `Diagnostic` ломает все места, где её создают или сравнивают в тестах; сначала посчитать их через `grep`.
