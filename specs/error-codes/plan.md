# Коды ошибок — план

- `flp-core/check.rs`: `enum DiagKind` (крупные виды, не по одному на сообщение), поле `kind: DiagKind` в `Diagnostic`, метод `DiagKind::id() -> &'static str` (стабильный идентификатор вроде `duplicate-id`). Все сообщения идут через `Report::push` и обёртки `block_error`/`link_error`; вызовов около 50 (`check.rs`, `uart.rs`). Параметр вида обязателен, так что компилятор находит каждое место.
- `flp-core`: `DiagKind::ALL` для перебора в тесте.
- `flp-editor/help.rs`: `error_anchor(kind)` — исчерпывающий `match` вид → якорь; «Проверка схемы» в `help/08-errors.md` — подразделы `###` по одному на вид, в каждом строка «Вид `…`»; тест сверяет заголовки и виды в обе стороны.
- `flp-editor/app.rs`: ссылка «Что это?» в панели сообщений; `flp-ai`/`flp-mcp`: поле `kind` в ответе `check`.
- Риск: изменение структуры `Diagnostic` ломает все места, где её создают или сравнивают в тестах; сначала посчитать их через `grep`.
