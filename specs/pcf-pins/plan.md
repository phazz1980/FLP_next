# План: выводы на расширителях PCF

## Формат данных

В `logic.toml`, рядом с `[[var]]`, новый список расширителей:

```toml
[[expander]]
id = "relays"          # тот же вид id, что у блоков
chip = "pcf8574"       # pcf8574 | pcf8574a | pcf8575
address = 36
sda = -1               # -1 — выводы I²C по умолчанию
scl = -1
period = "20ms"        # период опроса входов
```

У блока новое необязательное поле `expander = "relays"`: тогда параметр `pin` блока —
номер вывода микросхемы (P0…P7 / P0…P15), а не GPIO. Блок без поля — как раньше. Поле
не мешает остальным параметрам (`#[serde(flatten)]` берёт всё прочее). Блок библиотеки
разрешает расширитель строкой `expander = true` в `[block]` (у `digital_in` и
`digital_out`); у остальных поле игнорируется с ошибкой проверки.

Старые проекты читаются без правок: нет `[[expander]]` — нет изменений.

## Крейты и файлы

- `flp-core`:
  - `expander.rs` (новый): `Expander`, `Chip`, число выводов, допустимые адреса, `ExpanderUse`
    (какой блок занял какой вывод), проверка списка.
  - `logic.rs`: `Logic.expanders`, `Block.expander`.
  - `library.rs`: `BlockDef.expander`.
  - `pins.rs`: `pin_uses` пропускает блоки с `expander` (GPIO они не занимают).
  - `check.rs`: новые `DiagKind` (вывод расширителя занят/вне диапазона, нет расширителя, один
    адрес дважды) со справкой по-русски; коды в `specs/error-codes`.
  - `edit.rs`: команды «создать/изменить/удалить расширитель», «назначить блоку расширитель
    и вывод» (общий набор команд для редактора и ИИ/MCP).
- `flp-codegen`: состояние каждого расширителя (`<id>_in`, `<id>_out`, время опроса),
  чтение всех входов в начале прохода и запись изменившегося байта (слова) в конце, в шаблоны
  блоков передаётся `expander` (id и номер вывода). Шаблоны `digital_in`/`digital_out`
  получают ветку `{% if expander %}`.
- `flp-editor`: в `dialogs.rs::pin_combo` источник «GPIO / расширители / Добавить...», окно
  создания расширителя, подписи в `panels.rs::left`, раздел «Расширители» в дереве
  (правка, удаление).
- `flp-ai`/`flp-mcp`: те же команды, что в `edit.rs`.
- Документы: `help/` (раздел про платы или отдельный), `library/README.md`, файл архитектуры.

## Риски

- Место вставки чтения и записи в цикле: сейчас код блоков идёт в порядке выполнения;
  чтение расширителей должно быть до первого блока, запись — после последнего. Смотреть
  `assemble` в `arduino.rs`.
- Формат проекта растёт: без `[[expander]]` ничего не пишется, снимки старых примеров
  неизменны (критерий 5).
- Отладка по USB (отпечаток схемы): новые поля попадают в отпечаток; проверить, что старые
  проекты дают прежний.
- Окно создания расширителя открывается из окна свойств: вложенный диалог в egui, нужен
  возврат выбора в исходное окно.
