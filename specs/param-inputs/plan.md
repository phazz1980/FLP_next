# План: параметр как вход

## Модель (flp-core)
- `Block.param_in: BTreeSet<String>` (TOML `param_in`), параметры, ставшие входами.
- Эффективное описание блока: `Library::resolve(logic, block)` добавляет к входам типа входы
  `PortDef` из `param_in` (имя = имя параметра, тип по таблице спеки, `default` = значение
  параметра). Результат кэшируется в `Library` по (тип, набор, поколение библиотеки) и живёт
  всё время программы, поэтому сигнатура `resolve` и 31 место вызова не меняются.
- `ParamDef.static_: bool` (`static = true` в block.toml) запрещает галочку.
- Правка `Project::set_param_input(lib, block, param, on)`: включает/выключает, при выключении
  удаляет связь и константу входа; в журнал — что удалено.

## Проверка
- Вход-параметр обычный вход: `check` ничего особенного не знает; пропуск связи не ошибка —
  работает константа параметра (`default`).

## Генерация (flp-codegen)
- В `arduino.rs` литерал параметра из `param_in` заменяется выражением входа (как для
  привязки к переменной, `param_vars`); `value`/`flag` — то же. Источник выражения уже есть
  в `inst.inputs`.
- Порядок выполнения учитывает связь (вход обычный).

## Симуляция (flp-sim)
- Параметры блока на каждом скане берутся из входов с тем же именем.

## Редактор
- Свойства блока: галочка «Вход» рядом с подходящим параметром; параметр гаснет.
- Холст, PDF, отладка: используют `resolve`, новые входы рисуются сами.
- Редактор блоков: галочка «static» у параметра (для пользовательских блоков).
- MCP/ИИ: команда `set_param_input`.

## Риски
- Шаблон использует параметр в статическом контексте — компилятор арудино выдаст ошибку;
  защита: флаг `static` и понятное сообщение при сборке.
- Кэш описаний при горячей перезагрузке библиотеки: ключ включает поколение.
