# WASM-модули на микроконтроллере — план

## ABI v2 (расширение ABI из `wasm-blocks`)
Типы значений — `f64`/`i32`; строки и данные — указатель+длина в линейной памяти модуля, хост копирует их сам.
Экспорты модуля: `step(dt_ms)`, необязательные `init()`, `on_message(topic_ptr, topic_len, ptr, len)`, `abi_version() -> u32`.
Импорты `flp` (то, что уже есть): `input`, `param`, `output`, `log`. Новые:
- Теги: `tag_get(id) -> f64`, `tag_set(id, v)` — обмен с мастером и другими модулями через таблицу тегов хоста.
- Шина: `publish(topic_ptr, topic_len, ptr, len)`, `subscribe(topic_ptr, topic_len)`; хост кладёт в `esp_event`/очередь,
  доставка — вызовом `on_message` между шагами.
- Узкий набор железа (только то, что нужно блокам FBD): `gpio_read/write`, `adc_read`, `pwm_write`, `millis`.
  Тонкая периферия (RMT, PCNT, MCPWM, DMA) не пробрасывается: остаётся нативным блоком мастера, модуль задаёт уставки.
- Модуль без прав на железо получает только `input/output/tag/publish`; список разрешённых импортов — в манифесте модуля.
Приём сообщений: хост кладёт байты в память модуля через его экспорт `alloc(len) -> ptr`, затем зовёт `on_message`.
Манифест — `module.toml` рядом с `.wasm`: `name`, `abi = 2`, `allow = [...]` (права на `gpio_read`, `gpio_write`, `adc_read`, `pwm_write`, `millis`).
Реализовано в `flp-sim` (`mcu.rs`, тесты `tests/mcu.rs`); железо на ПК — заглушка `StubIo`. Шаг `step` у всех модулей принимает `dt_ms: i32`.
Подсчёт: версия ABI проверяется при загрузке (`abi_version`), неизвестный импорт — ошибка с именем.

## Мастер-прошивка (нативный C++, шаблон рядом с `esp32.cpp.tmpl`)
- Core 0: железо и быстрые контуры; Core 1: задачи модулей (по задаче FreeRTOS на модуль).
- Рантайм на модуль с заранее выделенным блоком памяти (против фрагментации); горячая замена: пауза задачи → выгрузка →
  загрузка нового файла → запуск; выходы и состояние нативных блоков не сбрасываются.
- Сторож на каждый модуль (топливо/время шага); при зависании — перезапуск и запись в журнал с причиной.

## Крейты
- `flp-sim`: хост-ABI v2 с заглушками железа (то же, что на плате); бенч сравнения ПК/плата.
- `flp-codegen`: позже второй вывод «схема → WASM» (отдельная спека).
- `flp-build`: сборка мастера и заливка `.wasm` по USB/OTA (файловая система).
- Документы: `Архитектура и план.md` (раздел плагинов/WASM), `help/` — когда появится поведение.

## Риски
- Память ESP32 без PSRAM; скорость интерпретатора (10–30× медленнее нативного) — быстрое остаётся нативным.
- wasm3 почти не развивается; рантайм выбираем по замерам, ABI от рантайма не зависит.
- Расхождение ПК и платы (числа, порядок вызовов) — один общий набор тестовых модулей.

## Замеры прототипа (03.11.2026)
Плата: ESP32 DevKit (без PSRAM), COM10, ядро esp32 3.3.12, Wasm3 0.5.0. Скетч — `proto/mcu_proto/`, модуль — `proto/blink.wat`
(182 байта, импорты `flp.gpio_write`, `flp.millis`, экспорт `step`, `abi_version`). Модуль зашит в прошивку массивом (LittleFS — в задаче 4).
- ОЗУ на модуль (среда + рантайм + стек 2048 слов + модуль): ~5,5 КБ. Свободной кучи в начале ~296 КБ, самый большой блок ~110 КБ.
- Шаг `step` (быстрый путь, проверка времени): 3,74 мкс.
- Горячая замена (выгрузка + загрузка): 628 мкс.
- 1000 замен подряд: свободная куча и самый большой блок не изменились (290744 / 110580) — фрагментации нет.
- Заливка и запуск по USB работают; светодиод на GPIO 2 визуально не проверялся.

**Выбор:** wasm3 — по этим замерам подходит с большим запасом. WAMR и `wasmi` `no_std` не мерили (не нужны, пока wasm3 укладывается);
вернёмся к ним, если понадобятся возможности, которых нет в wasm3 (он почти не развивается). Ограничение: замерен только пустой «мигающий» модуль,
тяжёлые модули (строки, MQTT) дадут другие цифры ОЗУ.
