# Задачи: пользовательские платы

- [x] 1. `PinInfo`: подпись и владеющее предупреждение, без `Copy`; `BoardLayout` над `Chip`. Проверка: тесты `pins.rs`, `uart.rs`, `check.rs` проходят без изменения ожиданий.
- [x] 2. `boards.rs`: `BoardDef`, чтение/запись `board.toml`, проверка файла, `Boards::load` (встроенные + пользовательские). Проверка: roundtrip, повтор GPIO, GPIO вне чипа, битый файл не мешает остальным.
- [x] 3. `BoardLayout::of_board` ищет пользовательскую плату по `board.model` и `fqbn`; `check.rs` и `flp-ai` берут пины оттуда. Проверка: тест — пин вне таблицы → ошибка, занятый → предупреждение.
- [x] 4. `library.rs`: пропуск папки `boards` (тест `boards_folder_is_not_a_section`), поле `board` у блока, `fixed` у параметра, `bus` у вывода.
- [x] 5a. Встроенные блоки `library/pcf8574_out` и `library/pcf8574_in` (адрес, пины шины, полярность, `once`-инициализация `Wire`), `docs.md`, пример в `examples/`. Проверка: снимки генерации (в т.ч. два блока с разными адресами — один `Wire.begin`), `flp check`/`flp build` примера.
- [x] 5b. `devices.rs`: `[[device]]` платы → настроенная копия встроенного блока (адрес, шина, полярность, имена каналов зафиксированы). Проверка: тесты `devices.rs`; снимок для реле и входов A6 — в задаче 13.
- [x] 6. `check.rs`: блок чужой платы → ошибка по-русски (`DiagKind::BoardBlock`, справка «Блок чужой платы»). Проверка: тест `a_block_of_another_board`.
- [x] 7. Упаковка в `.flpn` (`user_boards/<id>/`, `pack_user_board`) и распаковка недостающей платы (`unpack_missing_boards` в редакторе и CLI). Проверка: тесты `packed.rs` (чистая библиотека + проект с платой, битая плата и небезопасные пути не пишутся). Не сделано: предложение синхронизировать версию платы, если у проекта и программы она разная.
- [x] 8. `.flpboard`: экспорт/импорт, проверка путей, конфликт id (`boardfile.rs`). Проверка: тесты `export_import_keeps_every_file`, `bad_files_are_refused`.
- [x] 9. Редактор: список плат из `Boards` в `boardcfg.rs` (имя платы, пресеты меню, таблица пинов для UART), подписи пинов в списках, блоки платы в палитре только для её проектов (`BlockInfo::fits_board`). Проверка: тест `a_user_board_has_its_name_and_a_stale_model_is_dropped`; вручную не смотрел.
- [x] 10. Редактор: окно `boardedit.rs` — вкладки «Плата», «Выводы», «Периферия» (добавить расширитель PCF: адрес, пины шины, полярность, имена каналов), «Описание»; «Создать на основе», «Удалить». Проверка: headless-тест сохранения в папку + ручной запуск (окно глазами пока не смотрели).
- [x] 11. Описание: просмотр в окне платы, добавление изображений в `images/`, перетаскивание. Проверка: тест копирования файла и ссылки (картинка в окне глазами пока не проверена).
- [x] 12. Импорт/экспорт `.flpboard` в редакторе (меню, перетаскивание), регистрация расширения в `assoc.rs`.
- [x] 13. Пример `examples/kc868_a6_relays/` (входы X1–X6 → реле K1–K6); плата лежит в самом примере: `user_boards/kincony_kc868_a6/` (`board.toml`, `docs.md` с пометками «не проверено»). Проверка: `flp check` без замечаний, `flp gen` (снимок `kc868_a6_relays.ino`, тест `examples_match_snapshots` подхватывает `user_boards/`), `flp build` для `esp32:esp32:esp32` — собрано, 19 % памяти. ## Сверка с критериями спеки

1. Сохранение — тест `saving_writes_the_board_and_loading_gives_the_same_form` (папка платы, `docs.md`, `images/`, повторная загрузка даёт ту же форму); после «Сохранить» вызывается `reload_library()`, а правки руками подхватывает горячая подгрузка (`library_stamp` смотрит всё дерево `user_library/`). Окно глазами не смотрели.
2. Тест `pins_of_a_user_board` (вывод вне таблицы — ошибка, занятый — предупреждение), `flp check` примера — без замечаний.
3. Блок чужой платы отклоняется (`a_block_of_another_board`), в палитре его прячет `fits_board` (глазами не смотрели). `flp gen` — снимок `kc868_a6_relays.ino`, `flp build` для `esp32:esp32:esp32` — собрано, 19 % памяти.
3a. Блоки `pcf8574_out` и `pcf8574_in`, снимок `pcf8574.ino` (два адреса — один `Wire.begin`); добавление расширителя — вкладка «Периферия» окна платы (глазами не смотрели).
4. Картинки и `docs.md` лежат в папке платы (тот же тест, что в п. 1, и копия платы с картинками); показ картинок в окне платы глазами не проверен.
5. `the_user_board_travels_in_the_project`, `a_project_folder_carries_its_board_in_user_boards`, `a_broken_packed_board_is_not_written`, `export_import_keeps_every_file`, `bad_files_are_refused`; вопрос при совпадении id — окно `boardio.rs` («Заменить существующую»), вручную не смотрели.
6. Тесты `pins.rs`, `uart.rs`, `check.rs` проходят без изменения ожиданий, снимки старых примеров тоже, кроме одного: в `modbus_rtu.ino` исчез дубль общего кода `#ifndef FLP_UART_EXECUTOR` — одинаковый текст `once`-раздела у блоков разных типов теперь выводится один раз (нужно для общей шины PCF8574, описано в `library/README.md`).
7. `broken_descriptions_are_explained`, `saved_boards_are_loaded_and_broken_ones_do_not_stop_the_rest`.
8. `examples/kc868_a6_relays/` проходит `flp check`; выводы и адреса на железе не проверены — сказано в `board.toml`, `docs.md` платы и в справке.

Не проверено: работа на реальной KC868-A6 (адреса PCF8574, выводы шины I²C у вашей ревизии); окна «Новая плата» и «Импорт платы», перетаскивание файлов и показ картинок проверены только тестами без графики. Отложено: предложение синхронизировать версию платы при расхождении в проекте и в программе (задача 7), расширители PCF8575.
