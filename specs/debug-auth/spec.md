# Пароль на отладку

## Цель
Если у проекта задан пароль (`[project] password`), отладочная прошивка не отдаёт
данные и не принимает команды по USB, пока хост не докажет, что знает пароль.
Без пароля поведение прежнее.

## Решения (согласованы 02.11.2026)
- Пароль один: тот же, что шифрует копию проекта в прошивке.
- Закрыта отладка целиком: значения, проект, статистика, форсировка, уставки.
  До входа плата отвечает только на приветствие (версия протокола, «нужен пароль»).
- Подбор пароля по копии прошивки принимаем как риск (копия проекта шифруется тем же паролем).

## Сценарии
1. Пароль задан, пароль введён верно: монитор, окно отладки, `pull` работают как раньше.
2. Пароль задан, не введён или неверный: «нужен пароль» / «неверный пароль», данных нет.
3. Пароля нет: ничего не меняется, ввод не требуется.
4. Сброс платы или переподключение: вход нужно повторить.

## Критерии готовности
- Прошивка не передаёт IMAGE/STATS/PROJECT/TEXT и игнорирует команды до входа.
- Неверный пароль не раскрывает ничего о верном (ответ одинаков).
- Пароль не передаётся по USB открытым текстом и не хранится в прошивке в чистом виде.
- CLI (`monitor`, `pull`, `upload --debug`), окно отладки в редакторе и MCP `read_live_values` умеют входить.
- Проверено на железе: верный, неверный, пустой пароль; без пароля в проекте.
- Справка `help/06-debug.md` обновлена.

## Вне задачи
- Защита от физического доступа (чтение флеш-памяти), шифрование канала, Wi-Fi-транспорт.
- Разные пароли на проект и отладку.
