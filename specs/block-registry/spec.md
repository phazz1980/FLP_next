# Каталог наборов блоков (block registry)

## Цель
Находить, ставить и обновлять чужие наборы блоков (`.flpblocks`) из публичного каталога, не ища файлы вручную.

## Решения
- Каталог публичный, хостится в организации GitHub (репозиторий `registry`, имя организации выбирает владелец).
- Каталог = файл `index.toml` в репозитории; добавление набора — pull request.
- Адрес каталога — настройка редактора, запасное значение зашито в код.
- Обновления только по кнопке, без проверки при запуске.
- Зависимости между наборами поддерживаются.
- Каталог открываем для чужих наборов только после `specs/block-signing/` (публичность делает подпись обязательной).

## Сценарии
1. «Каталог» в окне библиотеки: загружается индекс, список наборов с поиском по имени, описанию, автору.
2. У набора видны: автор, контакты, лицензия, версия, число блоков, список блоков, Arduino-библиотеки внутри, зависимости.
3. «Установить»: скачивается `.flpblocks`, проверяется sha256 из индекса, затем обычный импорт набора.
4. «Проверить обновления»: сравнивает версии установленных наборов с индексом, показывает, у каких есть новее; «Обновить» ставит новую версию.
5. Установка набора с зависимостями: показывается список недостающих наборов, пользователь подтверждает, ставятся все.
6. Удаление набора, от которого зависят другие установленные наборы, предупреждает об этом.
7. Нет сети или индекс недоступен: окно показывает ошибку, ранее установленное работает как обычно.

## Формат
- В `pack.toml` добавляются: `id` (`автор/имя`, уникален), `format` (версия формата набора), `requires` (список `id` с минимальной версией).
- Запись в `index.toml`: `id`, `name`, `description`, `author`, `license`, `version`, `url`, `sha256`, `requires`.
- Версия набора — целое число.

## Критерии готовности
- Индекс разбирается; битый или неполный индекс даёт понятную ошибку, а не падение.
- Файл с неверным sha256 не устанавливается.
- Набор с `format`, который редактор не знает, отклоняется с сообщением.
- Установка набора с зависимостями ставит их все или не ставит ничего.
- Цикл зависимостей и недостающая зависимость обнаруживаются до установки.
- Тесты в `flp-core`: разбор индекса, сравнение версий, разрешение зависимостей, проверка хеша (сеть подменяется заглушкой).

## Вне задачи
Свой сервер и загрузка наборов через редактор, рейтинги и отзывы, автообновление при запуске, подписи (отдельная спека `specs/block-signing/`), платные наборы, подпапки и зеркала каталога.

## Открытое

- Автоматическая сборка индекса из релизов (GitHub Action) — после первой версии.
