# Блоки-плагины на WASM

## Цель
Поведение блока для симуляции на ПК пишется на **любом языке, который собирается в WASM** (C/C++, Rust, Go/TinyGo,
Zig и др.), а редактор выполняет модуль у себя через wasmi. Главное — быстрый цикл: сборка модуля занимает около
секунды, загрузка в wasmi — микросекунды, поэтому автор правит исходник, пересобирает и сразу видит новое поведение
блока, не перезапуская редактор. Модуль изолирован: не видит файлы, сеть и память редактора.

## Сценарии
1. Кладу в `library/<block>/` или в набор рядом с `block.toml` файл `block.wasm`; блок появляется в библиотеке без
   перезапуска (горячая подгрузка, как у остальных блоков).
2. В редакторе блока открываю «Пробный прогон»: задаю входы и параметры, нажимаю «Шаг» или «Пуск» с шагом времени —
   вижу выходы блока, посчитанные модулем.
3. Модуль без прав не может открыть файл, сеть, порт; зависший модуль прерывается по лимиту топлива/времени.
4. Пересобираю модуль своим компилятором (clang, cargo, tinygo…) — редактор замечает новый `block.wasm` и перезагружает
   его сам, сохраняя введённые входы и параметры; результат виден сразу.
5. Блок с `block.wasm` экспортируется в набор `.crabblocks` вместе с модулем.

## Критерии готовности
- Интерфейс модуля — обычные экспорты и импорты ядра WASM (C ABI), без привязки к языку и без wasm-bindgen; примеры на C++ и Rust.
- Перезагрузка при изменении файла `block.wasm` без перезапуска, ошибка загрузки не роняет редактор и не стирает прошлый результат.
- Загрузка и вызов модуля через `wasmi` в отдельном крейте; ядро (`flp-core`) о WASM не знает.
- Лимиты: память, топливо; превышение — понятная ошибка по-русски в журнале, редактор не зависает.
- Тест: модуль-пример (считает `a + b` или фильтр) вызывается из теста, лимит топлива прерывает бесконечный цикл.
- Пример блока в `examples/` и страница справки.

## Вне задачи
WASM на самом микроконтроллере; компиляторы внутри редактора; сетевые права модулей;
подпись модулей (см. `specs/block-signing/`).

## Решено
- Модуль **симулирует блок на ПК**: считает выходы по входам и параметрам, храня своё состояние между шагами. В прошивку WASM
  не попадает; прошивка по-прежнему строится из `esp32.cpp.tmpl`.
- Язык модуля — любой, что даёт WASM; редактор ничего не компилирует (сборку делает компилятор автора); путь «ИИ пишет модуль» — позже.
- Модули, которым нужен WASI (Go `wasip1`), поддерживаются минимальными заглушками (вывод в журнал, без файлов и сети) отдельной задачей; TinyGo/C/Rust работают без WASI.
- Первая версия: один блок в окне пробного прогона редактора блока (входы задаются руками, выходы видны по шагам времени).
  Симуляция всей схемы — отдельная спека после этой.
