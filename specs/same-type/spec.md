# Однотипные входы переключателей

## Цель

Переключатели (`switch`, `mux`, `dms`) сейчас работают только с `float`. Нужно, чтобы:

- вход «Номер» (`sel` у `mux` и `dms`) и вход `in` у `dms` принимали любое число (`int` или `float`);
- входы данных (`a`, `b`, `c`… у `switch` и `mux`, `in` у `dms`) принимали любой тип
  (bool, int, float, string), но все одного типа; выходы получают этот тип.

## Сценарии

1. Мультиплексор выбирает одну из строк-сообщений по номеру `int` — выход строка.
2. Переключатель выбирает между двумя логическими сигналами — выход bool.
3. Демультиплексор раскладывает целое значение по выходам — выходы `int`, остальные 0.
4. На мультиплексор подали строку и число — проверка схемы сообщает о разных типах.

## Решения

- Новый тип порта `same` в `block.toml`: вход берёт сигнал любого типа; все поданные `same`-входы
  блока одного типа; `int` вместе с `float` даёт `float`, как неявное расширение.
- Выход `same` получает этот тип. Если на `same`-входы ничего не подано (только значения
  по умолчанию), тип берётся из значений по умолчанию.
- Неподключённый `same`-вход со значением по умолчанию чужого типа получает ноль нужного типа
  (`false`, `0`, `0.0`, пустая строка).
- `sel` у `mux` и `dms` — `number`. `in` у `dms` — `same`: выходы должны следовать типу `in`,
  а не номера, и `same` это даёт. Так `in` принимает любые числа и вдобавок bool и строки.

## Критерии готовности

- [x] `flp check` ловит разнотипные входы `same` и выход `same`, ушедший на вход чужого типа.
- [x] Снимок примера с `switch` (bool), `mux` (string, номер `int`) и `dms` (`int`) компилируется.
- [x] Старые примеры (`math_switch`, `math_more`, selftest) дают тот же код.
- [x] В редакторе тип `same` есть в списке типов портов конструктора блоков.

## Вне задачи

Тип `same` у других блоков (сравнение, триггеры) — по отдельной просьбе.
