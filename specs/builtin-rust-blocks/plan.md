# План: встроенные блоки на Rust

## Новый крейт `crab-blocks`
Зависит только от `crab-core`. Ни GUI, ни arduino-cli, ни wasmi.
- Переезжают из `crab-sim::builtin`: `Ctx`, трейт `Behavior`, реализации 30 блоков.
- Трейт блока:
  ```rust
  pub trait BuiltinBlock: Sync {
      fn behavior(&self) -> Box<dyn Behavior>;          // симуляция
      fn emit_cpp(&self, e: &CppCtx) -> CppParts;       // прошивка (позже рядом emit_rust)
  }
  pub fn get(kind: &str) -> Option<&'static dyn BuiltinBlock>;
  ```
- `CppCtx` — то, что сейчас получает шаблон: `id`, выражения входов (`input`), имена выходов (`output`),
  литералы параметров (`param`, с учётом параметров-входов и привязок к переменным), сырые значения (`value`),
  активные входы. Строит его `crab-codegen::arduino::render_block` из уже готовых карт — логика подстановок не дублируется.
- `CppParts` — те же части, что `Sections` (`global`, `setup`, `looped`, `functions`, `once_*`, `includes`);
  `crab-codegen` переводит их в `Sections` и дальше путь общий (комментарий с id, фоновые задачи, `Direct`).
- Код блока пишем обычным `format!`/`push_str` так, чтобы текст совпал с прежним выводом шаблона.

## Изменения в существующих крейтах
- `crab-sim::builtin`: оставляет «ручные»/железные (`digital_out`, `pwm_out`, `mqtt_publish`, `Sink`),
  остальное берёт из `crab_blocks::get(kind).behavior()`. Публичный API `crab-sim` не меняется.
- `crab-codegen::arduino::render_block`: порядок источников — шаблон в папке > `crab_blocks::get` > модуль `block.wasm` > ошибка.
  `FirmwareSource` в `crab-core` не трогаем (ядро не знает про `crab-blocks`): решение принимает генератор.
- `crab-codegen::simsrc`: разделить на «раскрыть шаблон в части» и «обернуть части в модуль симуляции»,
  чтобы обёртку можно было подать `CppParts` от Rust-блока (нужно для теста сравнения).
- `crab-codegen::preview` / редактор блока / `crab-ai get_block_type`: у блока без шаблона, но с Rust-кодом —
  пример C++ (выдача для экземпляра с параметрами по умолчанию), только чтение; создать свой блок «на основе» — из этого примера.
- `library/<блок>/esp32.cpp.tmpl` у 30 блоков удаляются (по мере переноса, вместе с проверкой снимков).

## Тест сравнения (`crates/crab-blocks/tests/` или `crab-sim/tests/builtin_cpp.rs`)
Для каждого блока: `emit_cpp` с входами `crab_in_i`/выходами `crab_out_i` → обёртка `simsrc` → `zig c++ --target=wasm32-freestanding`
→ прогон в wasmi; параллельно `behavior()`; сценарий входов и параметров (включая края: деление на 0, переполнение `int`,
`count` у И/ИЛИ, смена параметра на лету). Выходы равны. Без `CRAB_ZIG` — пропуск, как `template.rs`.
`template.rs` (сравнение шаблона с builtin) становится не нужен для перенесённых блоков — заменяется этим тестом.

## Формат данных
Не меняется: ни `block.toml`, ни проект. В папке блока просто нет `esp32.cpp.tmpl`.

## Риски
- **Типы.** Симуляция считает всё в `f64`, C++ — в `int`/`float`/`bool` (целочисленное деление, `%`, переполнение
  счётчика). Эталон — шаблон; найденные расхождения правим в Rust-симуляции и пишем в `tasks.md`.
- **Побайтное совпадение вывода** с minijinja (пробелы, переводы строк) — проверяется снимками; цель — ноль изменений.
- **Подмена пользователем:** раньше встроенный блок можно было поправить, отредактировав шаблон в `library/`.
  Остаётся: положить `esp32.cpp.tmpl` рядом — шаблон главнее.
- **ИИ** учился формату шаблонов на примерах встроенных блоков (`get_block_type`) — отдаём пример выдачи, чтобы не потерять.
- **Границы:** `crab-blocks` не должен тянуть `minijinja`/`wasmi`; тест с zig — в dev-dependencies.

## Архитектура
