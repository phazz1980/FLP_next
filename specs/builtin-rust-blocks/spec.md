# Встроенные блоки на Rust вместо шаблонов C++

## Цель
Логика встроенного блока без железа описывается **один раз, на Rust**: тот же код считает блок в симуляции
и выдаёт его C++ для прошивки. Сейчас у 30 блоков две независимые реализации — шаблон `esp32.cpp.tmpl`
и `flp-sim::builtin` — и ничто не проверяет, что они совпадают. После задачи расхождение ловит тест,
а шаблоны этих блоков удалены. Попутно — задел под Rust-вывод генератора (тот же блок выдаст `esp-hal`-код).

Путь «Rust → WASM → C» (`specs/wasm-firmware/`) остаётся экспериментальным и сюда не относится.

## Объём первого шага
Блоки, у которых уже есть реализация в `flp-sim::builtin` и нет железа (30):
`and or xor not rs_trigger sr_trigger t_trigger rising_edge falling_edge timer_on timer_off pulse generator
debounce counter hysteresis compare greater less add sub mul div mod min max limit scale switch mux constant`.

Остаются шаблонами: блоки с железом, библиотеками, сетью, UART (`digital_out`, `pwm_out`, `mqtt_publish` и т. п.),
а также пользовательские блоки и наборы (`user_library/`) — они по-прежнему расширяются файлами.
Остальные чистые блоки (биты, тригонометрия, `pid`, `scale_table`, текст, веб-виджеты) — вторым шагом.

## Сценарии
1. Ставлю `timer_on` в схему: `flp gen` выдаёт тот же C++, что раньше из шаблона; симуляция считает его тем же Rust-типом.
2. Разработчик правит логику блока в одном месте — меняются и симуляция, и прошивка; тест сравнения падает, если они разошлись.
3. Рядом с `block.toml` встроенного блока положили `esp32.cpp.tmpl` — шаблон главнее (как сейчас главнее модуля), можно подменить код, не пересобирая программу.
4. Редактор блока и ИИ (`get_block_type`) у встроенного блока без шаблона показывают пример выдаваемого C++ (только чтение), а не «шаблона нет».

## Критерии готовности
- У 30 блоков нет `esp32.cpp.tmpl`; `block.toml` и `docs.md` на месте.
- Снимки генерации (`crates/flp-codegen/tests/snapshots/`) и скетчи всех `examples/` не изменились побайтно
  (кроме осознанных правок, перечисленных в `tasks.md`).
- Тест сравнения: на каждый из 30 блоков сценарий входов/параметров; выдаваемый C++ собирается на ПК
  и даёт те же выходы, что Rust-реализация в симуляции (нужен `FLP_ZIG`, без него тест пропускается).
- `flp check`, отладка, форсировка, быстрый путь `Direct`, фоновые платы работают как раньше.
- Справка (`help/10-block-editor.md`, `help/05-build.md`), `library/README.md`, файл архитектуры, новости обновлены.

## Вне задачи
Rust-вывод генератора (`esp-hal`); блоки с железом; новые блоки; изменение формата `block.toml` и проекта;
путь Rust → WASM → C.

## Решено
- Замена — Rust-тип блока с двумя обязанностями: шаг симуляции и выдача C++ (ответ пользователя).
- Первый шаг — 30 блоков из `flp-sim::builtin` без железа (ответ пользователя).
- Приоритет источника кода прошивки: шаблон в папке > встроенный Rust > модуль `block.wasm` (предложено, можно поменять).
- Семантика при расхождении: эталон — текущий шаблон C++ (его поведение уже на платах пользователей);
  Rust-симуляция подгоняется под него, отличия записываются в `tasks.md`.
