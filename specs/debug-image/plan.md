# План: образ состояния и проект во flash

**Затронуто.** `flp-codegen` (`src/debug.rs`, `arduino.rs`): структура образа, скан-цикл, маска форсировки, встроенный архив; `flp-debug` (`protocol.rs`, `table.rs`, `session.rs`): новый кадр образа, карта смещений, команда выгрузки проекта; `flp-core`: поле `password` в `project.toml`, упаковка/шифрование архива; `flp-build`: передача архива генератору; `flp-editor`, `flp-cli`: «Открыть проект с платы» (`flp pull`), ввод пароля; `help/`, `Архитектура и план.md`.

**Образ.** Генератор берёт `DebugTable` (порядок выполнения), группирует по размеру типа (8→4→2→1 байт), внутри группы сохраняет порядок. Получается `struct __attribute__((packed)) FlpImage`; карта `имя → (смещение, тип)` кладётся в `DebugTable`, отпечаток считается и по карте. Рядом маска форсировки: массив флагов + значения только для форсируемых.

**Скан-цикл.** `loop()`: снимок входов в `FlpIn`, логика читает/пишет локальные значения, в конце копия выходов и наблюдаемых в `FlpImage` (под критической секцией/между сканами, если логика в отдельной задаче). Форсировка применяется после блока-источника, как сейчас.

**Протокол v3.** Кадр `IMAGE` (0x05): `seq`, смещение, данные (образ режется на куски до 255 байт; сборка по `seq`). `HELLO` несёт размер образа. Команды: `GET_PROJECT` (0x16) → кадры `PROJECT` (0x06) с кусками и общей длиной/CRC32. Формат `VALUES` v2 остаётся для старых прошивок (редактор говорит «обновите прошивку» при несовпадении).

**Проект во flash.** `.crab` (ZIP) → `const uint8_t FLP_PROJECT[] PROGMEM`; с паролем — ChaCha20-Poly1305, ключ из Argon2/PBKDF2 (соль в заголовке). Прошивка ничего не расшифровывает.

**Риски.** Размер flash на малых платах (проверка, предупреждение); атомарность копии образа при многозадачности; совместимость с фоновой прекомпиляцией (архив меняется на каждой сборке — вынести в отдельный объектный файл/компилировать последним); нагрузка пересылки на UART 115200 (образ 200 Б × 10 Гц — ок, замерить).
