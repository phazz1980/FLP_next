# План: вывод «схема → WASM»

## Две дороги
- **Прямой эмиттер** (`wasm-encoder` в новом `flp-codegen::wasm`): каждый блок — готовый кусок WASM. Модуль крошечный (единицы КБ), но
  логика 30 блоков получается в третий раз (шаблон C++, `flp-blocks`, эмиттер); сходство держит только тест сверки.
- **Rust-обвязка над `flp-blocks`**: генератор пишет маленький crate, где `step` вызывает `Behavior::step` блоков в порядке
  выполнения; сборка `cargo build --target wasm32-unknown-unknown` (цель уже установлена). Логика одна на ПК и плату по построению,
  но модуль тянет `std`/`String`/`flp-core` и может не влезть: мастер принимает `.wasm` до 64 КБ, а байты держатся в ОЗУ.

Выбор — по замеру размера (задача 1). Если обвязка укладывается в ~40 КБ на типовую схему — берём её; иначе эмиттер, а
`flp-blocks` остаётся эталоном для теста сверки.

## Затронутые крейты
`flp-codegen` (новый вывод рядом с `ArduinoCpp`, `Program` общий), `flp-build` (сборка обвязки, если выбрана), `flp-cli`
(`flp gen-wasm`), `flp-sim` (запуск готового модуля — уже есть `mcu`).

## Формат
`module.toml`: имя листа, `abi = 2`, `allow` по найденным железным блокам, таблица `[tags]` (имя тега → номер).
Железные блоки: вход → `gpio_read`/`adc_read`, выход → `gpio_write`/`pwm_write`; пины подставляются константами из проекта.

## Риски
- Размер модуля и стек wasm3 (4096 слов у слота).
- Блоки с несколькими состояниями и строками (`step_text`) — в первой версии отклоняются.
- Порядок выполнения внутри листа и связи между листами: связь через границу листа = тег.
