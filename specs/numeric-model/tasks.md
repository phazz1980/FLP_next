# Числовая модель — задачи

Эталон — модель из спеки, реализованная в `flp-sim` на 32 битах; один и тот же `.wasm` на ПК (wasmi) и на плате (wasm3)
должен давать одинаковые биты. Сверка эмиттера с симуляцией остаётся бит в бит на каждом шаге.

1. [x] ABI v3 в хосте `flp-sim/mcu.rs` (импорты по типам, манифест, версия) и прототипы `.wat` + эталон `proto/compare`. Проверка: `UPDATE_GOLDEN=1 cargo test -p flp-sim --test mcu`, затем без флага. Готово: слот `Word(u32)`, импорты `*_i/*_f`, сценарий с буквой типа (`in 0 f 1.0`, `in 2 i 7`), `out` — 4 слова по 8 hex. Мастер и `compare.ps1` ещё на ABI 2 (задача 4); тесты `wasm_emit` красные до задачи 3.
2. [x] Симуляция схемы (`flp-sim/schema.rs`) на `i32`/`f32` (значение с типом `Bool/Int/Float`, края из спеки): она остаётся эталоном для эмиттера, поэтому идёт сразу после ABI. Проверка: юнит-тесты на края; снимки перегенерировать после просмотра отличий (ожидаемо только округление `f32`). Готово: значения между блоками остались `f64` (точно хранит `i32` и `f32`), арифметика — в `flp-blocks/src/num.rs` в 32 битах по реальным типам портов (`flp_core::port_types`), выходы всех блоков квантуются по типу порта; таймеры — `u32`-разность мс (переход через 49 суток), счётчик — `i32` wrapping. Отклонение от плана: вместо значения с тегом — носитель `f64` + типизированная арифметика. Долг: abs/sq/sqrt/pow/trig/pid/scale_table/битовые блоки считают в `f64` и квантуются на выходе.
3. [x] Эмиттер `wasm.rs` на `i32`/`f32`, `now` — `i32`, края из спеки. Проверка: тесты эмиттера на значения краёв (ожидаемые биты записаны в тесте по модели). Готово: `wasm.rs` на `i32`/`f32` (ABI 3, 6 фиксированных импортов), `now` — `i32`; тест `numeric_edges_match_the_simulation` (переполнение `i32`, деление на 0, остаток, смешанные операнды). Ограничение: `mod` для `float` через `f64` совпадает с `fmod` при |a/b| < 2^24.
4. [x] Мастер: слоты 4 байта с типом, wasm3-связки, память из манифеста. Проверка: сверка ПК/плата, замер шага 24/60/120 блоков, запись в `wasm-on-mcu/plan.md`. Готово: `master.ino` на словах по 4 байта (импорты `*_i/*_f`, `abi_version = 3`, `in`/`param` с буквой типа, `out` — 8 hex на слово); на плате ESP32 `compare.ps1` — 4 строки побитово, замеры в `wasm-on-mcu/plan.md`. Память из манифеста не нужна: модули листов объявляют 0 страниц сами. Прототипы `.wasm` для платы: `EXPORT_WASM=<папка> cargo test -p flp-sim --test mcu -- --ignored export_prototypes`.
5. [x] Проверка схемы: запрет неявных преобразований типов, предупреждение о `float`-счётчике. Проверка: тест `flp check` на примере. Готово: по решению 4 `int → float` и смешение в арифметике остались разрешены (результат `float`), а `float → int`, `bool ↔ число` уже были ошибкой; новое предупреждение `float-counter` (переменная `float`, замкнутая через `add`/`sub`), страница справки «Счётчик на float», тест `loop_through_variable_is_allowed`.
6. [x] C++-вывод: `int32_t`/`float`, флаги `-ffp-contract=off -fwrapv` (вместо `uint32_t`-обёрток: те же биты без вспомогательных функций, покрывает и `count++`), насыщающий `float → int` (`flp_f2i`: NaN → 0; `float_to_int`, `mux`/`dms` по float-селектору, `pwm_out`, `limit` целого с float-границами), остаток целых `flp_mod` (0 и -1 → 0), деление всегда во `float`; таймеры уже считают разностью `millis()` (переход через ноль безопасен). Проверка: снимки; `examples/math_more` собирается; на ESP32 края (NaN, ±1e20, INT_MAX+1, INT_MAX², `x % 0`, `INT_MIN % -1`, a*b+c без слияния) дали ожидаемые биты (03.11.2026). Сверка C++ с симуляцией: `FLP_ZIG=tools/zig-x86_64-windows-0.17.0/zig.exe cargo test -p flp-sim --test builtin_cpp` проходит (текстовые блоки сценарием не покрыты).
6a. [~] Цель Arduino Uno/Nano (`arduino:avr:uno`/`nano`): вывод без кучи и `String`, статические состояния блоков, пины AVR в модели платы, оценка ОЗУ/флеша в проверке схемы. Проверка: пример (мигание + счётчик + таймер) собирается `arduino-cli`, отчёт о памяти совпадает со сборкой ±10 %.
6b. [~] Сверка AVR с эталоном: сценарий `proto/compare` на AVR (simavr или плата) — те же биты, что на ПК/ESP32; есть Arduino Nano (ответ пользователя 03.11.2026) — сверяем на ней через Serial (команды как у мастера: `in`/`tick`/`out`). Номер порта и вариант чипа (ATmega328P старый/новый загрузчик) уточнить при первой заливке.
7. [ ] `string[N]` и память под строки — отдельным шагом.
8. [ ] Справка `help/` и `Архитектура и план.md`; сверка с критериями спеки.
