# Числовая модель — план

## Затронуто
- `flp-core`: тип порта/сигнала (`bool`/`int`/`float`) уже есть в моделях блоков; проверка схемы запрещает неявные преобразования между типами.
- `flp-sim` (`schema.rs`, `mcu.rs`): эталонная симуляция сейчас на `f64` — переводим на значение с тегом типа (`Bool/Int/Float`) и операции модели (wrapping `i32`, `f32`, края из спеки). Это эталон для всех целей, поэтому правится первым.
- `flp-codegen/src/wasm.rs`: глобалы и локали `i32`/`f32` по типу сигнала; `now` — `i32`; `tag_get/tag_set/input/param/output` — по типам (`*_i`/`*_f` или один набор с типом в имени); версия ABI 3.
- `flp-codegen/src/arduino` (C++): `int32_t`/`float`, `-ffp-contract=off`, целые операции через `uint32_t`.
- `master.ino`: слоты входов/выходов/тегов хранят 4 байта + тип; wasm3-связки по типам; память модуля из манифеста.
- Прототипы (`blink.wat`, `counter.wat`) и эталон `proto/compare/golden.txt`; справка `help/`.

- AVR (Uno/Nano): `flp-codegen/src/arduino` (цель-плата), модель платы в `library`/`boards` (пины, FQBN), `flp-core` проверка
  бюджета ОЗУ/флеша; `flp-build` — `arduino-cli` с ядром `arduino:avr` (если ядра нет — подсказать установку, не ломая остальное).
  Горячей замены и отладки по USB на AVR нет в первой версии.

## Формат
- `module.toml`: `abi = 3`, типы входов/выходов/тегов (`type = "bool|int|float"`), размер памяти (`memory_pages`, 0 по умолчанию).
- Логика и TOML проекта не меняются.

## Риски
- Эталонная симуляция на `f64` менялась под разные тесты: переписывание сломает снимки; снимки пересоздаём только после проверки, что отличия — ожидаемые (округление `f32`).
- Блоки с параметрами-числами (`time_on` и др.) должны получить тип; неоднозначные — `float`, время — `int`.
- Таймеры/счётчики на границе `i32` — отдельные тесты.
