# Числовая модель (одна для всех целей)

Продолжение `specs/wasm-on-mcu/` и `specs/wasm-schema-output/`. Сейчас значения модуля — `f64`; на ESP32 это
программная математика (≈ 4 мкс на блок) и вдвое больше ОЗУ. Здесь вводим свою числовую модель с фиксированной
шириной, одинаковую на ПК (`flp-sim`), ESP32/STM32 (WASM и C++) и AVR (только C++).

## Цель
Схема даёт одни и те же выходы бит в бит на любой цели; ширина слова железа на результат не влияет.

## Приоритет
Главное — оптимизация работы на микроконтроллере (скорость шага, ОЗУ на блок, флеш), а не симуляция на ПК.
Целевые платы: ESP32 (WASM-модули и C++), STM32 (C++), **Arduino Uno/Nano (ATmega328P, 2 КБ ОЗУ, 32 КБ флеш,
8 бит, без FPU) — только C++**: wasm3 туда не входит, поэтому горячей замены модулей на AVR нет, схема
компилируется в скетч целиком и заливается через `arduino-cli`.

## Решения (ответы пользователя 03.11.2026)
1. Сразу все типы: `bool`, `int`, `float` (не «всё в f32» первым шагом).
2. Математические функции (`sin`, `exp`, `pow`…) пока вне модели.
3. Прежние правки (куски `step`, стеки, память 0 страниц) закоммичены отдельно.
4. (03.11.2026) Смешение `int` с `float` в арифметике допустимо и даёт `float`; два целых дают тип выхода по умолчанию, равный более старшему из них (сейчас единственный целый — `int`, позже — `int8/int16`). Запрещено то, что теряет данные или смысл: `float → int`, `bool ↔ число` — только блоком преобразования.

## Модель
- `bool` — 0/1; `int` — `i32`, переполнение по кругу (wrapping); `float` — `f32` IEEE-754; `f64` не используется.
- Тип сигнала известен статически (по типу порта); эмиттер выбирает представление сам: `bool`/`int` → `i32`,
  `float` → `f32`. Неявные преобразования только в явных местах (блок преобразования, порт другого типа — ошибка проверки).
- Время: `now` и таймеры — `i32` миллисекунды с переходом через ноль; сравнение разностью.
- Края (фиксируем и проверяем тестами): деление целых на 0 → 0; `mod` как остаток со знаком делимого, на 0 → 0;
  `float`→`int` с насыщением, NaN → 0; блок «Деление» при нулевом делителе даёт 0 (так документировано в блоке, как и раньше); сравнения с NaN ложны, кроме `!=` (истинно, как в IEEE); `min`/`max` — выбор `a<b?a:b` / `a>b?a:b`.
- C++-вывод: `-ffp-contract=off` (иначе `madd.s` на ESP32 меняет округление); целые через `int32_t`, без UB
  (сложение/умножение через `uint32_t`).
- Строки: `string[N]` — фиксированная ёмкость, N задаёт схема; при переполнении обрезка и флаг. Память под строки и
  JSON-буферы выделяется один раз при загрузке модуля; размер модуля в памяти задаётся точно (манифест).
- AVR (Uno/Nano): вывод в C++ по той же модели (`int32_t`, `float` 4 байта — совпадает с ESP32 и ПК). Состояние блоков
  — статические переменные, куча и `String` не используются; строки только `string[N]`. Бюджет ОЗУ и флеша показывает
  проверка схемы до сборки (≈ 2 КБ ОЗУ на всё, включая стек). Плата выбирается в `project.toml` (`fqbn = "arduino:avr:uno"` / `nano`).
- Оптимизация под узкие платы (после основного объёма): уменьшенные типы `int8/int16` для счётчиков и таймеров на AVR
  допускаются только как явный выбор пользователя или вывод компилятора схемы, если диапазон доказуемо мал; модель
  результата при этом не меняется (в диапазоне результаты те же).

## Сценарии
1. Один проект на ПК и на плате даёт одинаковые выходы (сверка как в `proto/compare`).
2. Схема со счётчиком, идущим дольше 16,7 млн, работает верно в `int`, а `float`-счётчик предупреждает проверка.
3. Таймер работает после 49 суток аптайма (переход `now` через ноль).

## Критерии готовности
- `flp-sim` и модуль на плате совпадают бит в бит на сценариях для `bool`/`int`/`float`, включая края из списка.
- Шаг 120 блоков на плате заметно быстрее 458 мкс; ОЗУ на блок меньше 280 байт (замер записать в `plan.md`).
- ABI v3 (`tag_get/tag_set/input/param/output` по типам) описан в `specs/wasm-on-mcu/plan.md`; версия проверяется при загрузке.
- Старые прототипы (`blink.wat`, `counter.wat`) и эталон сверки пересобраны.
- Справка `help/` описывает типы и поведение на краях.

- Пример на Uno/Nano (мигание + счётчик + таймер) собирается `arduino-cli`, влезает в ОЗУ/флеш, а проверка схемы
  заранее предупреждает, если не влезет.

## Вне задачи
Математические функции; `f64` как выбор пользователя; строки переменной длины в куче; WASM-модули на AVR;
отладка по USB на AVR в первой версии (позже, облегчённый протокол).

## Ответы на вопросы (03.11.2026)
1. Названия типов в интерфейсе остаются как в модели: `bool`, `int`, `float` (русские «целое/дробное/логика» — нет).
2. Пока только `int`; `byte` вводим в блоках шины (Modbus/UART), когда они переедут на модули.
