# План

Этапы идут по порядку; после каждого проект собирается и работает.

1. **Отладка в мастере.** Мастер хранит значения всех слотов модуля (сейчас только `outputs[8]`):
   команда `dump <модуль>` отдаёт слова всех блоков по карте, которую пишет `flp-codegen::wasm`
   (имя блока.порт → номер слота) и кладёт в `module.toml`; `force <модуль> <слот> <тип> <знач>` /
   `unforce`; `hash <модуль>` — отпечаток схемы. `flp-debug`: новый транспорт-клиент мастера
   (текстовые команды, тот же `Live`), редактор и `read_live_values` MCP меняют источник.
2. **Блоки с железом в мастер** по семействам: датчики 1-Wire/DHT, шины (I²C, PCF8574), UART/Modbus,
   сеть/MQTT/NTP/веб. Драйвер — в мастере, модулю дают права `allow` по классам (как gpio_*).
   Для каждого блока: тест, пример, правка `docs.md` и справки.
3. **Удаление C++**: `ArduinoCpp`, шаблоны, `flp-build` (compile/direct/stamp), старый `flp-debug`,
   команды CLI, пункты меню и кнопки, примеры, справка, тесты. `arduino-cli` остаётся для заливки мастера.

## Риски
- Этап 2 большой: на каждое семейство — драйвер в мастере (C++), переход блока на WASM-вывод и проверка на железе.
- Мастер растёт: следить за размером прошивки и ОЗУ на C3.
- Меняется формат `module.toml` (карта слотов): старые проекты пересобираются.
