# Только WASM: отладка в мастере, C++-сборка уходит

## Цель
Схема живёт на плате только как WASM-модули под мастер-прошивкой. Отладка работает через
мастер, а не через отдельную C++-прошивку; старая сборка скетча удаляется.

## Решено (04.11.2026)
- Блоки без WASM-вывода (сеть, MQTT, NTP, веб, Modbus, UART, датчики, шины, расширители)
  сначала переносим в мастер, C++ удаляем после (пункт «а»).
- У блоков из `library/` с одним C++-шаблоном переносим по одному, шаблон удаляем вместе с переносом.
- AVR (Uno/Nano) не поддерживаются.
- Отладка не перепрошивает плату: подключается к мастеру.

## Сценарии
1. Нажать «Отладка»: редактор подключается к мастеру, видны живые значения блоков схемы.
2. Менять уставки (`param`) и входы на ходу без перезаливки.
3. Форсировать значение блока/выхода и снять форсировку.
4. Редактор сверяет отпечаток схемы на плате со схемой в редакторе.
5. Пароль на отладку (`specs/debug-auth`) работает так же.

## Критерии готовности (проверяемые)
- На плате с мастером окно отладки показывает значения всех блоков листа (не только 8 выходов).
- Уставка меняется за < 1 с, форсировка держится до снятия и сбрасывается при `reset`.
- Отпечаток схемы совпадает/не совпадает — редактор говорит об этом.
- После отладки мастер остаётся на плате (ничего не прошивается).
- Пример из `examples/` с каждым семейством блоков собирается как модуль и проходит `crablogic check`.
- В репозитории нет `crab-codegen::ArduinoCpp`, `esp32.cpp.tmpl`, `crab-debug` старого протокола, команд `gen/build/upload` для скетча.

## Вне задачи
AVR; Wi-Fi-транспорт отладки (позже, транспорт — отдельный слой); скриптовые плагины.
