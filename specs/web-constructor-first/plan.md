# План: веб-страница создаётся в конструкторе

## Данные

Страница — отдельный файл проекта `web.toml` (в архиве рядом с `logic.toml`, в папке-примере тоже).
Логика отдельно от страницы: `logic.toml` про веб ничего не знает, кроме ссылок на теги виджетов.

```toml
title = "Насос"        # заголовок
bg = ""                # фон
password = ""          # пароль страницы (как в мастере сейчас)
system = true          # страница «Система»
pages = ["Главная", "Настройки"]

[[widget]]
id = "pump_btn"        # имя = имя тега
kind = "button"        # то же, что web_* сейчас: led, gauge, slider, switch, ...
page = 0
col = 1
row = 1
w = 2
h = 1
caption = "Насос"
# прочие параметры вида — как у соответствующего web_* блока (min, max, unit, цвет, ...)
```

Параметры виджета берутся из определения блока `library/web_<вид>/block.toml`: оно остаётся источником
описания видов и параметров, но блоком на листе больше не является (`class` = «веб-виджет», в палитру не попадает).
`web_net` (форма сети) и `web_chart` — такие же виджеты страницы.

## Теги

- `crab-core`: из `web.toml` строится список веб-тегов: виджет с вводом → два тега `<id>.in` и `<id>.out`,
  индикатор → `<id>.out`, виджет без обратной связи → `<id>.in`. Тип тега определяет вид виджета
  (число, логический, текст). Они доступны проверке схемы как обычные теги; ссылка на несуществующий виджет —
  ошибка «веб-виджет удалён».
- Переименование: операция ядра `rename_web_widget` меняет `web.toml` и ссылки в `logic.toml` одной правкой
  (через общий механизм правок с откатом, как у блоков).

## Редактор (`crab-editor`)

- Левая панель, раздел «Веб-интерфейс»: список виджетов (имя, тип), перетаскивание тега на лист; кнопки
  добавления убраны, есть одна кнопка «Конструктор» (запускает `crablogic-web` с открытым проектом).
- Палитра блоков: `web_*` и `web_ui` не показываются. Панель сети больше не создаёт `web_ui`.
- Конструктор следит за `web.toml`: правка видна в панели без перезапуска (перечитывание по времени изменения
  файла, как уже сделано для листа).

## Конструктор (`crab-web`)

- Пишет и читает `web.toml` напрямую (не `logic.toml`). Добавление, удаление, переименование виджета и страницы,
  перетаскивание. Раздел «Не размещённые» уходит: виджет создаётся сразу на странице.
- Предпросмотр остаётся той же страницей, что отдаёт мастер.

## Сборка и доставка (`crab-codegen`, `crab-build`, мастер)

- `crab-codegen/src/wasm/web.rs`: `web_setup` берёт раскладку и таблицу виджетов из `web.toml`, а не из блоков листа.
  Модуль, которому нужна страница, ссылается на виджеты по таблице; хеш таблицы (id+вид+порядок) кладётся в `module.toml`.
- Мастер-прошивка (`specs/wasm-on-mcu/proto/master/master.ino`): новая команда протокола «загрузить страницу»
  (раскладка + таблица, до 8 КБ), хранение в Preferences (рядом с настройками сети), отдача страницы из флеша
  при запуске; ответ на запрос хеша. При старте модуль сверяет свой хеш таблицы с хешем страницы мастера и
  при расхождении пишет ошибку. Плата без страницы отдаёт заглушку «страница не загружена».
- Заливка одной командой: `crablogic gen-wasm --upload` и кнопка редактора сначала спрашивают хеш страницы на плате;
  если он отличается от `web.toml`, шлют страницу, затем модули. Отдельной команды заливки страницы нет.
- Обычный скетч: убираются эмиттеры `net.rs` для сервера `crabWebSrv` и `web.rs`, блоки `web_ui` и виджеты в
  Arduino-пути; `crablogic gen` для проекта с `web.toml` выдаёт сообщение «веб работает только в модулях WASM».
  `web_ui` и `web_*` как блоки схемы из библиотеки удаляются; их `block.toml` превращаются в описания видов виджетов.
- Протокол мастера меняется, версию протокола поднять (мастер нужно перезалить).

## Риски

- Объём: страница до 8 КБ во флеше и Preferences — проверить предел значения (4000 байт на ключ в Preferences:
  потребуется разбить на куски или писать в файл LittleFS).
- Расхождение хеша таблицы: правка страницы без перезаливки модуля → ошибка при старте, не падение.
- Удаление `web_ui`/виджетов ломает примеры (`web_ui`, `net_setup`, `web_wasm`, `web_wasm`-подобные): их переделываем
  в тот же шаг, снимки обновляем.
- Размер мастера почти не меняется (хранение страницы), но проверить на ESP32-C3 (раздел 2 МБ).
- Не проверено на железе до отдельной проверки.
