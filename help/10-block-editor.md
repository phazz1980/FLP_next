# Редактор блока

Открывается через «Библиотека → Новый блок...» или правой кнопкой на блоке в библиотеке («Посмотреть / Изменить блок...»). Встроенные блоки открываются только для просмотра — кнопка «Создать копию» делает из него свой блок. Свой блок сохраняется в `user_library/` и появляется в библиотеке сразу, без перезапуска.

Кнопка «🗖 На всё окно» в левом верхнем углу растягивает редактор на всё окно программы, «🗗 Обычный размер» возвращает его назад.

Вверху окна — как блок выглядит на плате (картинка обновляется по мере правок) и общие поля, ниже — вкладки.

## Общие поля

- **Название** — как блок называется в библиотеке. Тип блока в схеме берётся из названия при первом сохранении и потом не меняется.
- **Обозначение** — короткая надпись на самом блоке (`TON`, `&`, `a + b`).
- **Где лежит** — набор, раздел или папка в библиотеке; для нового блока выбирается из списка.
- **Хранит состояние** — блок помнит значения между циклами (таймеры, триггеры, счётчики); обратные связи допустимы только через такие блоки.
- **Один на проект** — такой блок в проекте может быть только один (Wi-Fi, NTP).
- **Библиотеки** — библиотеки Arduino для `arduino-cli` через запятую, можно с версией: `OneWire@2.3.8`. Недостающие сборка ставит сама.

## Входы и выходы

Имя порта — буквы (можно русские), цифры и `_`, без пробелов. По имени порт связан в схеме и в коде. Входы, выходы и параметры не могут называться одинаково, имена `id` и `type` заняты. При переименовании порта ссылки на него в шаблоне кода обновляются сами.

Типы: `bool`, `int`, `float`, `string`; у входа ещё `any` (любой) и `number` (любое число). Неявно приводится только `int` → `float`.

- **Если не подключён** (только входы) — значение входа, к которому ничего не подключено. Для `bool` выбирается из списка: `true`, `false` или «обязателен». Пусто или «обязателен» — вход обязательно надо подключить, иначе проверка схемы сообщит об ошибке.
- **Условие when** — порт есть на блоке, только пока условие верно; см. ниже.
- **Описание** — подсказка при наведении и строка в справке по блоку.

Стрелки двигают строку, ✕ удаляет её.

## Условие when

Условие делает порт или параметр необязательным: он появляется на блоке, только когда условие истинно. Пусто — «всегда».

Условие — выражение Jinja, то же, что в `{% if %}` шаблона. Переменные в нём — **параметры этого же блока**; других имён нет (проверка скажет «нет такого параметра»). Значения: `bool` — `true`/`false`, `int` и `float` — числа, строка и выбор — строки, время (`1s`, `500ms`) — миллисекунды.

| Условие | Когда порт или параметр есть |
|---|---|
| `count >= 3` | параметр `count` не меньше 3 (так в блоке И растёт число входов) |
| `mode == "input"` | выбран режим «input» |
| `use_reset and time > 1000` | включён `use_reset` и время больше секунды |

Пока условие ложно, порта нет, подключить к нему связь нельзя, а скрытый вход не требует подключения. Скрытые параметры не учитываются при подсчёте занятых пинов. Если условие записано с ошибкой, порт считается включённым, а ошибку покажет проверка схемы. Параметр не может зависеть в условии от самого себя.

## Параметры

Параметры задаются в свойствах блока, а не подключаются проводами.

- **Вид**: `bool`, `int`, `float`, `string`, `duration` (время: `1s`, `500ms`) и `pin` (вывод платы; рядом выбирается режим).
- **По умолчанию** — пусто значит «обязателен»: без значения проверка сообщит об ошибке.
- **Мин., Макс.** — границы для чисел.
- **Статический** (число, время) — значение нужно при генерации кода (`{{ value.имя }}`, размер массива): такой параметр нельзя сделать входом. Для остальных числовых параметров в свойствах блока есть галочка «Вход»; шаблон получает вместо литерала выражение входа, суффикс `UL` после `{{ param.имя }}` при этом отбрасывается. Если шаблон использует `value.имя` и параметр сделали входом, генерация сообщит об этом.
- **Условие when** — параметр показывается, только пока оно верно.
- **Под блоком** — что писать под блоком на листе: `имя=значение`, только значение, пароль со звёздочками или ничего.

## Код ESP32

Блок можно оставить **без шаблона**: если рядом лежит `block.wasm` (например, написанный на Rust), прошивка строится из него, см. «Прошивка из модуля» ниже. Если шаблон есть, он главнее модуля.

У **встроенных блоков** (И, ИЛИ, таймеры, счётчик, сравнение, арифметика, выводы, датчики, расширители PCF8574, UART и Modbus и т. п.) шаблона нет: их код написан на Rust внутри программы. Вкладка «Код ESP32» показывает C++, который такой блок выдаёт (имена портов — `in_имя`, `out_имя`, параметров — `param_имя`), только для чтения; «Новый блок на основе этого…» делает из него обычный блок с шаблоном, который можно править.

Над шаблоном поле **Заголовки**: файлы для `#include` через запятую (`DHT.h, Wire.h`).

Шаблон кода Arduino C++ (язык шаблонов — minijinja), с подсветкой: ключевые слова, типы, числа, строки, комментарии и `#include` раскрашены, подстановки `{{ … }}` и `{% … %}` и маркеры разделов `// @setup` выделены своими цветами. Подстановки:

- `{{ input.имя }}` — значение входа, `{{ output.имя }}` — переменная выхода, `{{ param.имя }}` — параметр как литерал C++;
- `{{ id }}` — id блока в схеме (им начинают имена своих переменных и функций);
- `{% if value.имя %}…{% endif %}` — код, который попадёт в скетч только при нужном значении параметра.

Шаблон делится на разделы: `// @global` — переменные блока, `// @setup` — код в `setup()`, `// @loop` — код цикла, `// @functions` — функции. С пометкой `once` (`// @global once`) раздел попадёт в скетч один раз на все блоки. Кнопки «Вставить» над полем кладут нужную подстановку на место курсора. Русские имена портов в коде превращаются в латинские идентификаторы сами.

## Код C++ для платы

Вкладка для блоков с железом: датчик, шина, библиотека Arduino. Код лежит в файле `native.cpp` рядом с `block.toml` и встраивается в **мастер-прошивку** платы. Он только получает данные (читает датчик) и отдаёт их в схему выходами; логику строят блоки схемы. Менять этот код — значит заново прошить мастер («Залить мастер-прошивку»). Вкладка «Код ESP32» (шаблон для обычного скетча) от неё независима: у блока могут быть обе, одна или ни одной.

Файл описывает себя сам:

```cpp
// crab:native libs="Adafruit BMP280" i2c=0x76
// crab:sim temperature=21.5
#include <Adafruit_BMP280.h>
struct State { Adafruit_BMP280 dev; };
CRAB_INIT(State& s, Params p)        { s.dev.begin(0x76); }
CRAB_STEP(State& s, In in, Out& out) { out.temperature = s.dev.readTemperature(); }
```

- `// crab:native libs="..." ключ=значение` — библиотеки Arduino для установки и ресурсы блока (пин, шина, адрес).
- `// crab:sim выход=значение` — что показывать на выходе при симуляции на компьютере (там этот код не выполняется).
- `CRAB_STEP(State& s, In in, Out& out)` — обязательная функция, вызывается каждый цикл. `in.<вход>` — входы, `out.<выход>` — выходы.
- `CRAB_INIT(State& s, Params p)` — необязательная: вызывается при первом цикле и при смене параметров; `p.<параметр>` — параметры блока.
- `struct State` — данные одного блока (у каждого экземпляра своя копия). Если её нет, мастер подставит пустую.
- Типы портов и параметров — только `bool`, `int`, `float` (время и пин — `int`); имена — латиница, цифры и `_`. Текстовые порты пока не поддержаны.

Кнопка «Создать по шаблону» (пока файл пуст) предлагает: пустую заготовку по входам, выходам и параметрам блока, датчик на I²C (параметр «address», чтение регистра через `Wire`), датчик на 1-Wire (DS18B20, пин берётся из параметра-пина блока) и «Библиотека Arduino (мастер)» — шесть шагов без набора C++: библиотека и заголовок; класс объекта, параметры блока и аргументы конструктора; вызовы при запуске; выходы (имя, тип, вызов, условие «когда»); действия по фронту входа; проверка с готовым кодом. Параметры, входы и выходы шагов сами появляются в блоке; пока в шагах есть ошибки (красные), блок не сохраняется. «Править код» переводит блок в обычный текст C++, обратно в мастер нельзя. Недостающие параметры и выходы шаблон добавляет в блок сам; числа и регистры правятся по даташиту датчика. Кнопки «Вставить» вставляют `in.`, `out.`, `p.` в место курсора. Под полем показываются ошибки разбора (с номерами строк) или «Файл разобран, ошибок нет». Блок с ошибкой в этом файле не сохраняется. «Собрать мастер для проверки» собирает мастер с этим блоком (один экземпляр) для платы открытого проекта (без проекта — ESP32 DevKit) и показывает ошибки компилятора C++; нужно ядро ESP32 («Файл → Ядра ESP32»). Заливки на плату нет.

## Описание

Текст `docs.md` в Markdown: что делает блок и пример. Показывается в этой справке на странице блока; справа от поля — предпросмотр.

Над полем — кнопки шаблонов: **Ж** (жирный), **К** (курсив), `код`, заголовки H1–H3, списки, цитата, блок кода, таблица и ссылка. Кнопка оборачивает выделенный текст (без выделения вставляет заготовку и выделяет её, чтобы сразу печатать поверх). Списки, цитата и заголовок работают со строками выделения, повторное нажатие снимает разметку.

«Картинка...» берёт файл png, jpg, gif или bmp и вставляет строку `![описание](images/имя.png)`. При сохранении блока файл копируется в папку `images/` блока и едет вместе с ним в `.crabblock`; картинки, которых больше нет в тексте, из папки убираются. Картинка занимает строку целиком; показывается в предпросмотре и в справочнике блоков.

## Пробный прогон

Запускает на этом компьютере **модуль симуляции** блока — файл `block.wasm` в папке сохранённого блока. Модуль нужен только для проверки поведения в редакторе; в прошивку он не попадает, она строится из шаблона на вкладке «Код ESP32».

Вводите значения входов и параметров, нажимайте «Шаг» (один шаг времени) или «Пуск» (шаги идут сами, каждый в реальное время), «Сначала» сбрасывает состояние модуля. Выходы показаны справа, строки, которые модуль вывел через `log`, — в журнале внизу.

Файл `block.wasm` редактор проверяет несколько раз в секунду: пересобрали модуль своим компилятором — новое поведение видно сразу, введённые значения остаются. Если новый файл не загрузился, на экране ошибка, а работает прежний модуль.

Модуль можно написать на любом языке, который собирается в WASM (C/C++, Rust, Go/TinyGo, Zig…), и он изолирован: не видит файлы, сеть и память редактора. Зависший модуль (бесконечный цикл) прерывается по лимиту выполнения, память ограничена 16 МБ.

**Интерфейс модуля** — обычное ядро WASM без привязки к языку.

| Что | Сигнатура |
| --- | --- |
| экспорт `step` | `step(dt_ms: i32)` — один шаг, `dt_ms` — прошедшее время в мс |
| экспорт `init` (по желанию) | `init()` — вызывается при загрузке и по «Сначала» |
| экспорт `memory` (для `log`) | линейная память модуля |
| импорт `crab.input` | `input(index: i32) -> f64` — вход по номеру в `block.toml` |
| импорт `crab.param` | `param(index: i32) -> f64` — параметр по номеру в `block.toml` |
| импорт `crab.output` | `output(index: i32, value: f64)` — задать выход |
| импорт `crab.log` | `log(ptr: i32, len: i32)` — строка UTF-8 в журнал |
| импорт `crab.input_text` | `input_text(index: i32, ptr: i32, cap: i32) -> i32` — текст строкового входа копируется в память модуля, возвращается длина |
| импорт `crab.param_text` | `param_text(index: i32, ptr: i32, cap: i32) -> i32` — то же для строкового параметра |
| импорт `crab.output_text` | `output_text(index: i32, ptr: i32, len: i32)` — задать строковый выход (UTF-8) |

Логические, целые и дробные значения передаются как `f64` (`bool` — 0 или 1). Номера считаются по порядку `[[input]]`, `[[output]]` и `[[param]]`. Состояние хранится в самом модуле между шагами.

### Симуляция из кода блока

Если писать модуль вручную не хочется, редактор соберёт его сам из шаблона на вкладке «Код ESP32». Нужен компилятор [zig](https://ziglang.org/download/): распакуйте его куда удобно (в git он не входит, папка `tools/zig/` игнорируется).

1. «Файл → Симуляция блоков»: включите «Собирать симуляцию пользовательских блоков» и укажите «Путь к zig» (кнопка «Обзор...», «Проверить» запускает `zig version`). По умолчанию выключено.
2. Сохраните блок: в фоне собирается `block.wasm`, на вкладке «Пробный прогон» виден статус («собирается», «собрана», «не собрана: …»). Дальше модуль подхватывается как обычно.

Если zig не указан или не найден, симуляция из шаблона просто не добавляется, без ошибок. Блок, который работает с железом или библиотеками (`pinMode`, `digitalRead`, `Serial`, `Wire`, `WiFi`, `#include`, UART), не симулируется: статус называет причину и номера строк, выходы задаются вручную, как у встроенных блоков с платой. Тригонометрия и `pow`/`exp`/`log` тоже не поддерживаются.

Собранный модуль помечается пустым файлом `block.wasm.generated` рядом. Свой `block.wasm` без метки редактор никогда не заменяет; чтобы вернуть автосборку, удалите его.

### Прошивка из модуля (без шаблона C++)

Блок без `esp32.cpp.tmpl` и с `block.wasm` попадает в прошивку: модуль переводится в C программой [w2c2](https://github.com/turbolent/w2c2) и вставляется в скетч, у каждого экземпляра блока своё состояние. Один исходник даёт и симуляцию, и прошивку.

1. Модуль пишется на `no_std` Rust (или другом языке) и общается с блоком только через `crab.input/param/output/log`, экспорты `step` и `init`; память не больше одной страницы (64 КБ) с заданным максимумом. Лишние импорты отклоняются с названием блока.
2. «Файл → Симуляция блоков»: поле «Путь к w2c2» (кнопка «Проверить»). Путь можно не задавать, если задана переменная `CRAB_W2C2` или `w2c2` есть в `PATH`.
3. Перевод идёт сам: при сохранении блока, при сборке в редакторе и при `crablogic gen`/`crablogic build`. Рядом появляются `block.wasm.c` и метка `block.wasm.c.generated`; пока `block.wasm` не менялся, перевод не повторяется. Свой `block.wasm.c` без метки не заменяется.

Ограничения: только числа и логика (`f64`; строки не поддерживаются), до 16 входов, параметров и выходов; код модуля занимает флеш (около 0,5 КБ у таймера) и работает медленнее шаблона C++ (на ESP32-C3 около 2,8 мкс против 1,5 мкс на шаг у таймера). Образец — `library/timer_on_rs` (исходник в `src/`, сборка `build.cmd`), пример проекта — `examples/wasm_ton`.

Примеры на Rust и C++ с готовым `block.wasm` лежат в `examples/wasm_block/` (блок «Фильтр сглаживания», `build.ps1 rust` или `build.ps1 cpp`). `block.wasm` едет с блоком в набор `.crabblocks`.
