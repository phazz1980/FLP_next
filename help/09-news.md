# Что нового

Список изменений запущенной версии — «Справка → Что нового в этой версии». Полный перечень версий лежит в релизах на GitHub. Ниже самое заметное.

## 1.3.0

- Виджеты, добавленные в веб-конструкторе, больше не пропадают: если в редакторе были несохранённые правки, веб-страница из изменённого файла всё равно подхватывается, и автосохранение её не затирает.
- Заливка модулей с отладкой на маленьких платах (ESP32-C3): мастер даёт задаче модуля стек по размеру модуля и, если памяти не хватило, пишет причину в журнал (`log`) вместо молчаливой остановки; журнал мастера короче (24 записи); в отладочный модуль попадают не более 128 наблюдаемых сигналов.
- Обновление прошивки по сети (OTA) убрано: у блоков `wifi` и `ethernet` больше нет параметров «Загрузка прошивки», «Обновление по сети» и «Пароль OTA», со страницы «Система» исчез раздел загрузки. Прошивка заливается по USB. В старых проектах удалите эти параметры и связь со входом пароля OTA.
- Веб-страница теперь создаётся только в веб-конструкторе и хранится в проекте отдельным файлом `web.toml` (виджеты видны в левой панели, раздел «Веб-интерфейс»; кнопок добавления нет). Веб работает только в модулях WASM: в обычном скетче его нет, `flp gen` для проекта с веб-страницей сообщает об этом. Удалённый в конструкторе виджет оставляет в схеме связи, проверка выдаёт ошибку. Старые проекты с блоками `web_ui` на листе не поддерживаются.
- Редактор блока разворачивается на всё окно (кнопка «🗖 На всё окно»), в справке есть кнопки размера шрифта «A−» / «A+».
- Флажки «Включить» у Wi-Fi, Ethernet, MQTT и веб-страницы не ставят блок на лист: он ждёт в панели, пока его не перетащат («Блок целиком»). Веб-страницу включает флажок «Включить» в разделе «Веб-интерфейс» левой панели (блок страницы создаётся в проекте, на лист не ставится); рядом кнопка «Конструктор страницы...». Виджет, созданный в конструкторе, на лист сам не попадает: он виден только в левой панели, раздел «Веб-интерфейс». Виджет можно вытащить на лист несколько раз, как переменную: на листе каждый раз появляется его изображение (`<виджет>_2`, `_3`), все изображения работают с одним виджетом страницы, а сам виджет на лист не ставится. Пока ни одного изображения нет, строка виджета в панели подсвечена. Удаление с листа не удаляет виджет из проекта.
- У блоков `wifi` и `ethernet` убран параметр «Веб-страница»: веб-сервер на порту 80 есть всегда, страницы на нём показывает блок «Веб-интерфейс». В старых проектах параметр `web` в `logic.toml` можно удалить.
- Если у веб-страницы снят флажок «Включить», обычная сборка скетча больше не отказывается из-за веба: блоки страницы и виджеты при сборке, проверке и отладке просто не учитываются.
- Адрес платы в нижней строке снова показывается при отладке через мастер: мастер сообщает его в ответе на `list` (строка `ip=...`). Мастер нужно перезалить.
- При запуске редактор проверяет, что на компьютере есть ядро ESP32 для arduino-cli; если его нет, предлагает скачать (раньше оно ставилось только при первой сборке).
- Отладочный скетч убран: «Залить» всегда ставит мастер-прошивку (раньше при включённой 🛠 заливался скетч с отладкой, и модули потом не принимались), кнопка 🛠 теперь относится только к заливке модулей.
- Удаление блока Wi-Fi, Ethernet, MQTT или веб-страницы с листа больше не выключает флажок «Включить»: блок уходит с платы, но остаётся в проекте со всеми настройками и ждёт в левой панели. Выключает его только флажок.
- Снятый флажок «Включить» у веб-страницы больше не удаляет блок: настройки страницы (заголовок, страницы, пароль) и виджеты остаются, в прошивку страница просто не попадает.

## 1.2.0

- Сверка проекта с платой по хешу (протокол v5, прошивку нужно перезалить): при подключении редактор говорит, совпадает ли открытый проект с тем, из которого собрана прошивка, и предлагает скачать версию с платы. Команда `flp hash`, сверка в `flp monitor`.
- Пароль на отладку: если в проекте задан пароль, отладочная прошивка не отдаёт значения, проект и статистику и не принимает форсировку, пока хост не войдёт по запросу-ответу (протокол v4, прошивку нужно перезалить). Редактор, `flp monitor`, `flp pull` и MCP входят сами, пароль по кабелю не передаётся.
- Проект хранится в памяти платы (по желанию зашифрованный паролем из `project.toml`) и читается обратно: «Файл → Открыть проект с платы...», `flp pull`. Значения отладка передаёт образом памяти (протокол v3, прошивку со старым протоколом нужно перезалить). Пример `examples/blink_protected`.
- Веб-конструктор: виджет, добавленный в редакторе, появляется в правой панели «Не размещённые» (его строка по умолчанию 0); перетащите его на страницу или щёлкните — он встанет в конец текущей страницы. Пока конструктор запущен, правки веб-виджетов в редакторе сохраняются в файл сразу. В прошивке неразмещённые виджеты стоят под остальными.
- «Веб-ввод числа»: параметр «Целое число» делает выход целым (`int`) вместо дробного; при смене параметра связь с выходом нужно перевесить.
- «Веб-ввод текста»: вход `write` разрешает запись со страницы (ноль — страница не может менять текст; без связи запись разрешена); начальный текст, скрытый ввод, страница и цвета в свойствах блока больше не показываются — они задаются в веб-конструкторе (мастер-прошивку нужно перезалить).
- Веб-ввод текста (`web_text_input`): поле ввода строки на веб-странице, в том числе скрытое для паролей. Пример `examples/net_setup` — плата поднимает свою точку доступа, на странице `http://192.168.4.1/ui` вводятся SSID, пароль, брокер, логин, Client ID и пароль MQTT, они применяются на лету, а индикаторы показывают, подключилась ли плата и есть ли связь с брокером.
- Блоки с железом (`digital_in`, `digital_out`, `analog_in`, `pwm_out`, `dht22`, `ds18b20`, `flash_store`, `dms`, `decoder`, `encoder`, `cycle_report`, `pcf8574_in`, `pcf8574_out`) тоже переписаны на Rust, шаблонов у них больше нет; скетчи не изменились. Симулируются блоки без выводов (`dms`, `decoder`, `encoder`, `flash_store`, `cycle_report`); у блоков с пинами и датчиками симуляции пока нет. UART и Modbus (`uart_config`, `uart_read`, `uart_send`, `modbus_*`) тоже на Rust: шаблонов нет, скетчи не изменились. Сеть и веб-блоки пока на шаблонах
- Сеть (`wifi`, `ethernet`, `mqtt*`, `ntp`) и веб-интерфейс (`web_ui`, `web_net`, все виджеты) тоже переписаны на Rust, UART и Modbus — тоже: шаблонов `esp32.cpp.tmpl` у встроенных блоков не осталось, скетчи не изменились побайтно
- Клиент MQTT: выходы `connected` и `error` включаются, как у Wi-Fi. Блоки Wi-Fi, Ethernet и клиент MQTT можно перетащить на лист целиком (значок ▢ в левой панели в разделе сети), как публикации и подписки.
- Выделенные блоки заливаются голубоватым цветом целиком, а не только рамкой. Флажков «Вход» в левой панели сети больше нет: параметр делается входом только в свойствах блока.
- Выделенные блоки сдвигаются стрелками клавиатуры (шаг сетки, с Shift — пять шагов).
- Блок, который тянут с зажатым Shift, остаётся на своём листе, а границы листа раздвигаются вслед за ним (без Shift он переходит на лист под ним).
- Свойства блока: колонка «Вход» справа, логические параметры — переключатели вкл/выкл; режим Wi-Fi и текстовые параметры сети (SSID, пароль, адреса Wi-Fi и Ethernet, брокер, порт, логин, пароль и идентификатор клиента MQTT) тоже можно сделать входами; при смене значения связь переустанавливается.
- Виртуальный стенд в симуляции: цифровые и аналоговые входы, DHT22, DS18B20, цифровые и ШИМ-выходы считаются как на плате; уровень пина и сигнал датчика (значение, линейное изменение, ошибка) задаются правой кнопкой по выходу блока Теперь и сеть: обрыв Wi-Fi/Ethernet, недоступный брокер MQTT, регистры и «нет ответа» у Modbus-мастера, регистры собственного Modbus-slave (запись мастера и записи программы) и ввод строк в UART.
- Встроенные блоки без железа (логика, триггеры, таймеры, счётчик, сравнение, математика, биты и слова, строки, ПИД, таблица масштаба, `switch`, `mux`, `constant`) переписаны на Rust: одна реализация считает и симуляцию, и код прошивки; скетчи не изменились. Шаблонов `esp32.cpp.tmpl` у них больше нет, редактор блока и ИИ показывают сгенерированный C++
- `arduino-cli.exe` лежит в папке программы, ядро ESP32 — в `esp32core` рядом; поиск: папка программы → система → предложение скачать фиксированные версии (arduino-cli 1.5.1, ядро 3.3.12). Сборка архива: `build-dist.ps1 -WithCore` кладёт ядро в архив
- Блоки-плагины на WASM: файл `block.wasm` рядом с `block.toml` симулирует блок на компьютере, вкладка «Пробный прогон» в редакторе блока; модуль перезагружается при каждой пересборке. Примеры на Rust и C++ — `examples/wasm_block/`
- Симуляция схемы на компьютере: «Проект → Симуляция схемы на ПК» — схема считается без платы, значения видны на листах, входы и уставки задаются щелчком по значению; кнопка «▶» на панели; переменные считаются
- Прошивка из блока на Rust/WASM: блок без шаблона C++ с `block.wasm` переводится в C через w2c2 и попадает в скетч (образец `library/timer_on_rs`, пример `examples/wasm_ton`); путь к w2c2 — «Файл → Симуляция блоков», `FLP_W2C2` или `PATH`
- Параметры как входы: в свойствах блока у числовых параметров галочка «Вход» (в том числе у пользовательских блоков, флаг «статический» запрещает); работает в коде, симуляции и через команду ИИ `set_param_input`
- Симуляция из кода блока: при сохранении пользовательского блока `block.wasm` собирается из шаблона через zig («Файл → Симуляция блоков», по умолчанию выключено; без zig симуляция не добавляется)
- Строки в симуляции: блоки группы «Строки» и IP-адреса считаются, текст виден на связях, строковые переменные проекта работают, строковые порты и параметры доступны модулям `block.wasm` и симуляции из шаблона; веб-элементы ввода стартуют с «начального» значения, публикация MQTT даёт импульс; строковый выход блока с железом задаётся руками
- Время цикла в порт теперь блок «Время цикла в порт» (`cycle_report`), а не пункт меню «Проект»; секция `[diagnostics]` в `project.toml` больше не читается
- Язык комментариев в скетче следует за языком интерфейса: русский — русские, остальные — английские
- Замена типа блока без перекладывания связей: правая кнопка по блоку → «Заменить блок на»

## 1.0.0

- Программа теперь называется CrabLogic: новые имена программ (`crablogic-editor.exe` и др.), логотип и расширения файлов — проект `.crab`, плата `.crabboard`, блок `.crabblock`, набор блоков `.crabblocks`. Старые файлы `.flpn`, `.flpboard`, `.flpblock`, `.flpblocks` по-прежнему открываются. Настройки переехали в `%APPDATA%\CrabLogic` (переносятся сами при первом запуске).
- Прямая пересборка: если после правки схемы изменилось только тело скетча, программа сама компилирует и компонует прошивку командами прошлой полной сборки, без arduino-cli. Сборка и заливка после правки идут в 2–3 раза быстрее; в журнале — строка «Прямая сборка». При любом сбое — обычная сборка через arduino-cli.
- Фоновая сборка запускается только когда она действительно нужна: сменились библиотеки, подключаемые файлы, плата или её настройки. Обычные правки схемы больше не нагружают компьютер.
- PDF с картинкой плат строится через Typst, с таблицами параметров блоков; используются системные шрифты.
- Переключатели, мультиплексор и демультиплексор принимают любой тип: все подключённые входы должны быть одного типа (int и float дают float), выход получает этот тип. Пример — `examples/switch_types`.
- ИИ-помощник: кэширование запроса и средний уровень рассуждений по умолчанию — ответы дешевле и быстрее (`FLP_AI_EFFORT=high` возвращает прежний).
- Язык интерфейса: «Вид → Language / Язык» — русский, English, 中文, Español, हिन्दी, বাংলা. Переведены меню, диалоги и сообщения редактора; справка, описания блоков и сообщения проверки схемы пока остаются по-русски. Хинди и бенгальский рисуются без сложной шейпинг-вёрстки (ограничение egui), поэтому буквы могут выглядеть неидеально. Словари — `crates/flp-editor/i18n/*.json`: ключ — русская строка из кода.

- Свои платы: «Библиотека → Новая плата...» описывает плату — чип, выводы с подписями с платы, распаянную периферию, схемы и текст. Плата выбирается в «Проект → Настройки МК...», хранится в `user_library/boards/`, кладётся внутрь проекта `.crab` и переносится файлом `.crabboard` («Библиотека → Экспорт платы», «Импорт платы из файла...» или перетаскивание файла на окно). Подробности — в разделе справки «Свои платы».
- Новые блоки «PCF8574: выходы» и «PCF8574: входы» (группа «Расширители») для расширителей ввода-вывода на шине I²C. Плата с такими микросхемами даёт готовые блоки «Реле» и «Входы» без ввода адресов.
- Входы и выходы на расширителях PCF: в свойствах цифрового входа и выхода можно выбрать вывод PCF8574, PCF8574A или PCF8575 вместо GPIO, а новый расширитель создать там же. Занятые выводы подписаны «занят: блок», повтор ловит проверка. Расширители проекта собраны в дереве («Расширители»); ИИ и MCP получили команды `set_expander`, `remove_expander` и `place_on_expander`. Пример — `examples/pcf_pins` (не проверен на железе).
- Выводы платы с функциями: таблица выводов в «Новая плата» теперь пуста, выводы добавляются кнопкой «+ Вывод», им даётся название с платы и отмечаются функции — цифровой вход, цифровой выход, ШИМ, АЦП, ЦАП (в пределах возможностей чипа). Блоки предлагают только выводы с нужной функцией. Блок `pwm_out` и режим `pwm` для параметров-выводов; старые платы работают как раньше.
- Выводы расширителей на плате: в «Новая плата → Выводы» можно описать, какие выводы распаянных PCF8574 плата выводит наружу, как они подписаны и что умеют. В свойствах входа и выхода такие выводы лежат в одном списке с GPIO («Плата: … · P0 · K1»): выбор строки ставит блок на вывод и сам заводит расширитель; проверка ловит вывод, которого плата не выводит.
- Вход и выход, как переменная, создаются в дереве слева («+»), не попадая сразу на лист, и вытягиваются на плату мышью. Двойной щелчок по входу, выходу и переменной в дереве открывает свойства. Одиночный щелчок находит блок на листе, повторный — следующий экземпляр (копию тега или блок той же переменной).
- Копии входов и выходов: перетаскивание из дерева тега, который уже стоит на плате, ставит его копию, а не переносит блок. Настройки у копий общие, связи свои; у выхода побеждает последняя копия по порядку выполнения. Пример — `examples/tag_copies`.
- Вход или выход, которого нет ни на одном листе, подсвечивается в дереве жёлтым «(не используется)», как переменная. Удаление с листа последнего экземпляра оставляет его в дереве; из проекта он удаляется правой кнопкой в дереве — «Удалить из проекта».
- Пример `examples/kc868_a6_relays` — Kincony KC868-A6: входы X1–X6 включают реле K1–K6. Выводы и адреса взяты из описаний производителя, на железе не проверены.

## 0.4.11

- Редактор блока: при переименовании входа, выхода или параметра (в том числе на русском) ссылки на него в шаблоне кода обновляются сами — раньше вкладка «Код ESP32» показывала ошибку про старое имя.
- Редактор блока: колонка «Подпись» убрана из таблиц входов, выходов и параметров (подписи, уже записанные в блоках, сохраняются).
- Редактор блока: для входа типа bool значение «Если не подключён» выбирается из списка (true, false или «обязателен»).
- Новый раздел справки «Редактор блока» (в том числе про условие `when`) и кнопка «? Справка» в самом редакторе блока: открывает справку на текущей вкладке.
- Редактор блока: поле «Заголовки» перенесено на вкладку «Код ESP32»; при прикреплении библиотеки её главный заголовок вписывается туда сам.
- Окно «Новый набор блоков» занимает четверть экрана.
- Подсветка синтаксиса C++ в шаблоне блока, в пробной генерации и в окне «Код проекта»; в шаблоне отдельным цветом выделены `{{ … }}`, `{% … %}` и маркеры `// @setup`.
- Описание блока: кнопки шаблонов форматирования (жирный, списки, таблица, ссылка и др.) и вставка картинок — они хранятся в папке блока и видны в справочнике.
