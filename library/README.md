# Библиотека блоков

Каждый блок — папка `library/<тип>/`. Имя папки совпадает с `type` в `block.toml`.

## Встроенные и пользовательские блоки

- **Встроенные** — эта папка `library/`, они идут с программой. Менять их нельзя: в редакторе
  они открываются только для просмотра, а на их основе можно сделать свой блок.
- **Пользовательские** — папка `user_library/` рядом с `library/` (в корне репозитория), формат тот же.
  Их создаёт редактор блоков и ИИ-помощник (`create_block_type`). Пользовательский блок не может
  занять тип встроенного: такой блок пропускается с предупреждением.

Обе папки читают редактор, `flp` и MCP-сервер. В редакторе у библиотеки две вкладки —
«Встроенные» и «Пользовательские»; новый блок — «Библиотека → Новый блок…» или кнопка во вкладке
«Пользовательские», а правая кнопка на блоке даёт «Посмотреть / Изменить блок…», «Новый блок на
основе этого…» и для своих блоков «Удалить блок…». В окне редактора видно, как блок выглядит
на плате, и есть вкладка «Пробная генерация».

| Файл | Зачем |
| --- | --- |
| `block.toml` | название, группа, входы, выходы, параметры, описание |
| `esp32.cpp.tmpl` | шаблон кода Arduino C++ для ESP32 |
| `docs.md` | пояснение и пример (по нему же ИИ подбирает блоки) |

## block.toml

```toml
[block]
type = "timer_on"          # совпадает с именем папки
name = "Задержка включения" # как показывать в редакторе
group = "Время"            # папка в библиотеке редактора
description = "..."
symbol = "TON"             # короткое обозначение на блоке (по умолчанию — name)
memory = true              # блок хранит состояние между циклами
includes = ["DHT.h"]       # заголовки для #include в скетче
libraries = ["DHT sensor library"]  # библиотеки arduino-cli, `flp build` ставит недостающие
single = true              # в проекте может быть только один такой блок (Wi-Fi, NTP)
shared = "network"         # общий объект библиотеки (сеть, Modbus): на двухъядерных чипах
                           # блоки с меткой network сами уходят в фоновую задачу (ядро 0)

[[input]]
name = "in"
label = "Вход"             # необязательно: подпись на блоке и в свойствах, можно по-русски
type = "bool"              # bool | int | float | string; у входа ещё any
default = false            # необязательно: значение, если вход не подключён
description = "..."

[[output]]
name = "out"
type = "bool"

[[param]]
name = "time"
type = "duration"          # bool | int | float | string | duration | pin
default = "1s"             # без default параметр обязателен
min = 0                    # необязательные границы для чисел
max = 100                  # (у duration — в миллисекундах)
show = "named"             # подпись под блоком: named — «имя=значение» (по умолчанию),
                           # value — только значение, secret — значение под звёздочками
                           # кроме первого и последнего знака, hidden — не показывать
local = "ssid"             # значение хранится в программе (%APPDATA%\FLP_next\local.toml)
                           # отдельно для каждого значения параметра ssid и не попадает
                           # в файл проекта; оба параметра строковые, нужен default
description = "..."

[[param.choice]]           # список значений: в свойствах — выпадающий список,
value = 0                  # под блоком — подпись варианта; другие значения
label = "Клиент"           # схема не примет (default должен быть в списке)

[[param]]
name = "pin"
type = "pin"
mode = "out"               # только для pin: io (по умолчанию) | in | out | adc —
                           # какие выводы платы подходят (выход не на «только вход»,
                           # adc — только выводы с АЦП)
shared = true              # только для pin: блоки этого типа могут делить вывод (шина 1-Wire)
min = -1                   # у pin с min < 0 значение -1 значит «не используется»
```

Выводы проверяются по плате проекта (ESP32, ESP32-C3, ESP32-S3; таблица в
`flp-core/src/pins.rs`): нет такого вывода, вывод флеш-памяти, не подходит по `mode` —
ошибка; UART0/USB — предупреждение. Один вывод у двух блоков (или у двух параметров
одного блока) — ошибка, кроме параметров с `shared`. В окне свойств вывод выбирается
из списка, занятые выводы видны, но недоступны.

Имена типов, портов и параметров — буквы (можно русские), цифры и `_`, без пробелов и точек:
по ним блок связан в схеме (`from = "блок.порт"`) и в шаблоне (`{{ input.in }}`, `{{ input.вход }}`).
В коде прошивки русские имена транслитерируются (`{{ id }}` блока «насос» — `nasos_1a2b3c`).
Чтобы на блоке и в окне свойств было название с пробелами, задайте `label` — у входа, выхода и параметра. Имена общие на весь блок
(входы, выходы и параметры не могут называться одинаково). Имена `id` и `type` заняты.

Неявное приведение типов только одно: `int` → `float`. Вход с `type = "any"`
принимает выход любого типа (и константу любого вида); шаблон узнаёт настоящий тип
из `{{ input_type.<имя> }}` — `bool`, `int`, `float` или `string` — и выбирает код
через `{% if %}`. У выхода типа `any` не бывает.
Тип `string` — это Arduino `String` (IP-адрес, сообщение, имя); со числами он
не смешивается: числа в строку и обратно переводят блоки группы «Строки». В онлайн-отладке
строки видны (до 64 байт), но не форсируются.

### Условия `when`

У входа, выхода и параметра может быть условие `when`: порт или параметр есть у
блока, только пока условие выполняется. Условие — выражение Jinja, как в
`{% if %}` шаблона; параметры блока в нём — просто имена, `duration` — в миллисекундах:

```toml
[[input]]
name = "val"
type = "int"
when = 'source == "input"'   # вход «время» появляется, только если выбран источник «вход»

[[param]]
name = "time"
type = "duration"
when = 'source == "const"'   # обязателен, только пока виден
```

- Отключённого порта нет на схеме и в коде: связь с ним — ошибка `flp check`,
  неподключённый отключённый вход ошибкой не считается.
- Отключённый параметр редактор не показывает, и он не обязателен; если у него
  есть значение, шаблон его всё равно получает.
- В условии можно упоминать только параметры блока, и параметр не может зависеть
  от самого себя — это проверяется при загрузке библиотеки.
- В шаблоне отключённого порта нет в `input` / `output`: обращайтесь к нему внутри
  того же условия — `{% if value.source == "input" %}{{ input.val }}{% endif %}`.

Вход без `default` обязательно должен быть подключён, иначе `flp check` выдаст ошибку.
У выходов `default` не бывает: до первого цикла они равны false / 0.

`memory = true` разрешает обратные связи: цикл в схеме допустим, только если
проходит через блок с памятью. Связь, замыкающая цикл на такой блок, получает
значение с прошлого цикла программы; цикл без блока с памятью — ошибка `flp check`.

## Шаблон кода

Шаблон делится на разделы строками-маркерами; любой раздел можно опустить:

- `// @global` — глобальные переменные состояния блока;
- `// @setup` — код в `setup()`;
- `// @loop` — код в `loop()`, выполняется в порядке схемы;
- `// @functions` — функции блока; в скетче стоят перед `setup()`, поэтому
  объявлять прототипы не нужно.

Эти разделы повторяются для каждого экземпляра блока, поэтому имена в них
начинаются с `{{ id }}`. Код, общий для всех экземпляров, пишется в разделах с
пометкой `once`: `// @global once`, `// @setup once`, `// @functions once`.
Одинаковый текст такого раздела попадает в скетч один раз, а разный — по разу на
каждый вариант. Например, шина на выводе из параметра:

```cpp
// @global once
OneWire bus_{{ param.pin }}({{ param.pin }});   // одна шина на каждый вывод
// @functions once
float read_bus(OneWire &bus) { ... }            // одна функция на весь проект
// @loop
{{ output.out }} = read_bus(bus_{{ param.pin }});
```

Раздела `// @loop once` нет: код цикла выполняется для каждого блока в порядке
схемы. Общий код идёт раньше кода экземпляров и помечен комментарием
`// <тип>: общий код`.

Подстановки в синтаксисе Jinja (minijinja), доступны условия `{% if %}`:

| Запись | Что подставляется |
| --- | --- |
| `{{ id }}` | id блока, префикс для его переменных: `{{ id }}_start` |
| `{{ input.<имя> }}` | выражение со значением входа |
| `{{ input_type.<имя> }}` | настоящий тип входа: `bool`, `int`, `float`, `string` (для `any` — тип подключённого выхода) |
| `{{ output.<имя> }}` | переменная выхода, ей присваивается значение |
| `{{ param.<имя> }}` | значение параметра как литерал C++ |
| `{{ value.<имя> }}` | значение параметра как число или строка — для условий: `{% if value.on > value.off %}` |
| `{{ uart.<поле> }}` | настройки UART блока (см. «Блоки на UART»): `serial`, `input`, `number`, `speed`, `config`, `parity`, `rx`, `tx`, `de`, `rx_buffer` |

Параметры `duration` подставляются числом миллисекунд, `pin` — номером вывода,
`bool` — `true`/`false`, `float` — с суффиксом `f` (`2.0f`). Неподключённый вход
с `default` подставляется литералом (у `string` — `String("...")`).

Выход можно читать в своём же шаблоне: это значение с прошлого цикла
(так устроены RS-триггер и счётчик).

## Блоки на UART

Скорость, формат и выводы аппаратных UART задаются один раз в настройках платы
(`[[uart]]` в `project.toml`), а блок указывает, какой UART берёт и как:

```toml
[block.uart]
param = "port"         # int-параметр блока с номером порта: -1 — USB, 0, 1, 2 — UART
access = "write"       # exclusive | write | read | config
```

- `exclusive` — порт настраивает библиотека блока (Modbus RTU); больше никто его не использует;
- `write` — блок только отправляет; таких блоков на одном порту сколько угодно;
- `read` — блок принимает; читатель у порта один;
- `config` — блок сам задаёт настройки порта своими параметрами `speed`, `format`,
  `rx`, `tx`, `de`, `rx_buffer` (так устроен «Настройки UART»); порт тогда не
  настраивается в «Настройках МК», а владельцем блок не считается.

Порты с `write` и `read` открывает сам генератор в начале `setup()`
(`setRxBufferSize`, `begin` с форматом и выводами, режим RS-485 при выводе DE).
В шаблоне доступны готовые значения: `{{ uart.serial }}` — `Serial1`,
`{{ uart.config }}` — `SERIAL_8N1`, `{{ uart.parity }}` — 0/1/2 и т. д.
Номер `-1` — это USB (`Serial`): у него нет настроек, скорость 115200, блоки могут
писать и читать (не `exclusive`). Аппаратные UART — 0, 1, 2 (`Serial0`…`Serial2`), какие
есть у платы: ESP32 — 1 и 2 (её UART0 — это USB-мост), ESP32-C3 — 0 и 1, ESP32-S3 — 0, 1, 2.
Читателю в шаблоне нужен `{{ uart.input }}`, а не `{{ uart.serial }}`: в отладочной
прошивке байты USB заняты отладкой, и ввод консоли приходит через `flp_dbg_input`
с теми же `available()` и `read()`.
Проверка схемы ругается на ненастроенный UART, на UART, которого нет у платы,
на двух владельцев одного порта и на выводы UART, занятые блоками.

## Переменные

Переменные объявляются в `logic.toml` и используются на платах встроенными
блоками `var_get` (чтение, выход `out`) и `var_set` (запись, вход `in`):

```toml
[[var]]
name = "setpoint"
type = "float"        # bool, int, float, double, String и другие типы Arduino
init = 22.0           # значение после включения, по умолчанию false / 0

[[block]]
id = "setpoint_r"
type = "var_get"
var = "setpoint"
```

Читать переменную можно сколько угодно раз и на любой плате, записывать — в одном
месте. В пределах цикла запись выполняется раньше чтения; если чтение и запись
образуют петлю, чтение берёт значение с прошлого цикла. Переменная, которую никто
не записывает, — уставка с начальным значением. В скетче переменная называется
`var_<имя>`. Пример — `examples/tags`.
